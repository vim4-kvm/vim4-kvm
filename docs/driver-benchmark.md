# 驱动基准

本页管原生采集与编码测量的准备和判读；参数、默认值及报告字段以[C 工具](../tools/vim4-driver-bench.c)帮助与源码为准。
默认排除解析、像素读取、写盘、网络和应用；工具不代替调用者取得独占。
导航：[准备](#构建与离线回归)、[后端](#后端与输入)、[判读](#指标解释)、[校验](#独立验证图像)。

## 构建与离线回归

先在 Linux ARM64 具备 GStreamer 开发依赖的环境编译，按源码头注释运行离线夹具。
采样前完成构建并核对同一二进制；工具不会切内核、加载模块、停应用或改变 HDMI 源。
新报告独占创建，不覆盖旧结果；锁只协调本工具实例，不能替代真实独占检查。

## 后端与输入

参数选择对应运行内核的后端，插件、分配器和环境以实际应用启动器为准。
主线用父 buffer 租约与 DMA 平面视图，不复制原帧；厂商用原有 VFM 编码链。
缩放须有驱动能力，报告实际输入和输出，不能把缩放结果当旧主采集；
高刷先准备匹配源，JPEG 与视频编码的资格不同，见[高刷](video-modes.md)。
原生 HDR 的主采集不能强行协商为普通八位格式，须按能力选同源次采集。

厂商后端须使用生产应用的普通用户及兼容分配器，不能提权或重建共享互斥文件。
实际时钟读不到就缺测并补只读旁路证据。请求同样的码率和 GOP 不证明画质或固件行为一致。
停止实际消费者后采样，结束恢复；内核切换按[部署门禁](subsystems/deployment.md)执行。

## 指标解释

计数、实际 wall 时间和测量区间一起看，源封顶不代表编码器峰值。
CPU 的单核与整机口径须注明；工具测量不包含网络和浏览器，不叫端到端。
caps 中请求的 profile 或 level 不能证明实际 SPS；旧固件曾把请求 profile 解释错误，
已修正映射仍须真实码流验证，不能凭成功解码判定相符。
各阶段分位数不能直接相加，独立诊断不进入基线成绩。

硬件 JPEG 的离线录制帧探针以[工具](../tools/edge-jpeg-profile.py)为准。
等待、CPU copy、输入同步与哈希的计时范围分开；无输出复制仅诊断等待上限，不能生成可用视频。
同输入同质量哈希应一致，wall 包含校验而阶段计时不一定包含。
网页单帧预取与无队列原生入口不同，离线输入也不是现场 DMA 导入，不能混算吞吐。
历史分段证据见[下游测量](bringup/2026-10-25-video-downstream-latency.md)。
