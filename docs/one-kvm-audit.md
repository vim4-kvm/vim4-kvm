# One-KVM VIM4 功能复核（2026-10-14）

更新基线：One-KVM `98ba6784`，板上 `vim4-onekvm 2.5.1+vim4.20261014.10`，

## 当前明确不支持或缺外设

| 功能 | 当前边界 |
|---|---|
| ATX 电源/复位、状态检测 | 未连接 ATX 硬件，平台能力报告不支持；不可用普通 GPIO 冒充。WOL 是另一条软件路径，尚未验证目标机器唤醒 |
| 多虚拟盘 / 多 LUN | 适配层只接受 1 个 LUN；请求 8 个会明确失败 |
| USB 组合上限 | 最多 5 个 IN 端点；每个 HID、麦克风、磁盘各占 1 个，网卡占 2 个。设置与挂载 API 均拒绝超限组合 |
| USB 以太网桥接 | 网卡使用独立 DHCP/NAT；当前不桥接板子的现有以太网连接 |
| 蓝牙 / CH9329 HID | VIM4 平台只公布 OTG 和 none；额外后端未做本板适配验收 |

对应实现：[平台能力](../One-KVM/src/platform/linux.rs)、
[OTG 服务](../One-KVM/src/otg/service.rs)。这些边界需要新增适配或外设，不是打开开关即可支持。

## 已有实现，但尚未完成实机验收

| 功能 | 现有证据与仍需验证的部分 |
|---|---|
| RustDesk、VNC、RTSP | 保留原生服务和共享视频管线；板上当前均关闭。未验证客户端协商、音视频、控制和同时连接 |
| HDR 曲线 | 参数保存、重载已经验证；本轮输入为 SDR，One-KVM 的真实 HDR 画面效果尚未验收 |
| Ventoy | 256 MiB 创建、USB 枚举和主机读文件已通过；尚未验证通过 Ventoy 引导系统。新增自动网页文件读写/卸载脚本因用户开始使用虚拟盘未完整重跑 |
| 账户高级功能 | 基础初始化和登录通过；TOTP、账户修改、禁用认证等保留实现，未逐项走完实机流程 |
| Computer Use、Redfish、WOL | 保留实现，未配置外部模型/目标设备并端到端验证；Redfish 电源控制仍受 ATX 硬件缺失限制 |
| 截图、录像、粘贴/宏与快捷键 | 保留网页功能；已有基本键鼠证据不覆盖这些入口的全部行为 |
| 网络与恢复边界 | 未做公网 STUN/TURN、完整冷启动、HDMI 热插拔、长时间运行和异常断电恢复验收 |

## 已有实机证据的主功能

- H.264/H.265 4K 约 60 fps、MJPEG；输入状态、输出分辨率/帧率上限、码率与 MJPEG 质量。
- 4K60 / 1080p60 EDID 切换；共享 HDR 参数保存；视频设置重启保留。
- 实际键盘、鼠标；ISO 上传、主机读取与弹出后的键鼠恢复。
- Ventoy 引导资源随包安装，真实创建和文件读写单元测试不再静默跳过。
- 三应用往返切换；管理器趋势图、HDR 和应用入口共存。
- HDMI 测试音经 WebRTC 实际解码，最终包的 Web Audio 采样峰值 0.620；同时视频约 59.97 fps。
  Chrome 的 totalAudioEnergy 仍为 0，不能仅凭此统计判断无声；原 Opus WebSocket 路径也有非零 PCM 证据。

软件基线为 558 项 Rust 测试、7 项助手测试、42 项工作区测试和七组件包校验通过。
结论：核心本地 KVM 链路已适配，但不能称为 One-KVM 全功能验收完成。
