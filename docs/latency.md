## 优化指标与验收协议

以下是工程目标，须用当前版本建基线；历史 NanoKVM 数字不代表当前 PiKVM/One-KVM。先优化 PiKVM 与共享链路，共享改动回归四应用，H.264/H.265 分开出结果。

### 主指标与目标

| 指标 | 定义与4K60有线LAN目标 |
|---|---|
| 软件端到端 | 同机源开始绘制帧ID→该帧合成提交；报P50/P95/P99/max及样本数，目标≤60/75/90ms |
| 呈现间隔 | requestVideoFrameCallback 的 presentationTime 差；P95≤33.4ms、P99≤50ms；报>50/100/250ms次数及max，稳态无>250ms停顿 |
| 同连接增长 | 30分钟首尾相同120秒运动窗口，端到端P50/P95增长均≤16.7ms，不靠刷新恢复 |
| 更新率 | decoded FPS、presentedFrames增量各≥59fps；另报源实际更新率与回调跳号，重复源帧不算更新 |
| 完整性 | 受控无人工丢包LAN：零packetsLost/framesDropped/freezeCount增量、零三带不一致；异常轮次保留 |
| 画质/带宽 | 固定场景、尺寸、帧率和码率预算，报实际Mbps/峰值，检查小字、细线、运动；不能靠降质量/帧率/分辨率或加带宽换结论 |

等画质码率比须评估同参考片段/解码输出；同目标码率不等于同画质。回调是软件提交，expectedDisplayTime是预测，屏幕发光须另用光学设备测。

### 测试矩阵与运行条件

- 单观看者、4K60有线LAN，H.264/H.265各测60Mbps压力档和12Mbps受限档；静态小字、持续高速滚动、停止运动后恢复分别统计，不支持的组合明确标记。
- 初筛先稳定运动，预热≥15秒后测120秒；A/B/A至少三组配对。保留后做≥30分钟同连接耐久，首尾相同120秒运动窗口；16位ID约18分钟回绕，分窗口/源日志，连接不重建。
- 首连、新观看者、重连、关键帧恢复、切编码另做功能回归，报首帧/恢复耗时；人工丢包实验单列。
- 记录源码/包、应用与编码器PID、实际codec/尺寸/输入频率、码率/GOP/行刷新、浏览器版本/模式/屏幕Hz、音频开关、媒体网卡、温度、CPU/编码器时钟。音频开启为主验收条件，实际音频测试仍遵循[代码规范](code-standards.md#上板与测试)的用户授权。
- 构建与采样串行，独占板及HDMI源；并行编码、抓栈或配置/PID/路径变化使整轮受干扰，保留原始数据。板票与heavy规则见[队列](board-window.md#排队采样与迁移)。

### 测量有效性与接受改动的规则

- 像素回读会扰动GPU，报readbackCostMs，另跑 `--no-pixels` 配对流畅度；presentedFrames跳号是回调漏采，不能直接算丢帧。卡死须报无更新尾段，不能只算成功帧FPS。
- 时钟/ID校验以[summary](../tools/latency-summary.py)为准；旧日志不重新解释，不丢慢样本。每120秒≥1000有效标记才比较P99。
- 三组配对方向一致，目标分位数组间中位改善≥3ms且超过对照波动；否则无明确收益。P50不能抵消P95/P99、呈现尾部、冻结、画质、音频或恢复退步。
- 未达绝对目标的可靠无回归改进可保留，不能称达标。PiKVM 0/0已有尾间隔退步，仍需复测；Safari与物理端点未验。
- 不同帧/时钟的分段均值、分位数不能相加冒充端到端；队列容量、目标缓冲和平均FPS不足以证明成功。
- 保留日志/配置/失败轮次/配对分位数；无新收益保留已验配置并记录瓶颈，不无限缩缓冲或未验超频。

## 测量操作

依赖/登录/loopback统一见[公共前提](board-tools.md#浏览器测试的公共前提)。先编译并启动[源](../tools/latency-source.swift)，再用[接收器](../tools/latency-receiver.mjs)选择实际应用，最后[汇总](../tools/latency-summary.py)；用法、预热、选屏及参数以入口源码为准。
源和接收必须同Mac；源时长覆盖认证、预热及测量，使用专用浏览器。三带一致性两端同时启用，只比较同设置；稀疏采样可能漏短峰值。

## 长测与分段诊断

参数/日志字段以上述入口源码为准：

- 无像素配对测节奏，包含静默尾段与全观察窗推进；CPU画布hint可能先读整张纹理，不能因裁剪小就忽略扰动，hint也不保证实际放置。
- 固定浏览器仍核实际版本，自动更新使配对无效；外部CDP结束关测试context，保留外部进程。接口诊断只改本次测试ICE，核实际媒体路径，不改生产默认。
- 长测保持连接，按时间切源窗口再匹配回绕ID；首尾运动状态相同，边界须对齐周期快照，未切片重复ID日志不能直接汇总。
- [RTP汇总器](../tools/latency-rtp-summary.py)须喂独立解码验证的AU→RTP映射，不能按标称周期猜ID；全部回调与稀疏像素分布分列，均不含无回调帧。读到后继帧、未匹配和歧义不能隐藏。
- [分段汇总器](../tools/video-timing-summary.py)按PTS关联单观看者，拒绝重启/尺寸不符；交帧序号缺口不是完整源丢帧计数。启用方法与时钟端点见[VIDEO.md](../NanoKVM/deploy/vim4/VIDEO.md)。

## Board-side isolation and completed-frame mode

厂商采集完整帧模式用0x3（BIT0|BIT1），不使用缺同步的BIT2同缓冲读写。
`game_mode 0`、`HDMI_LOW_LATENCY=0` 恢复自动策略，不能作为强制off；off对照先3再c，并核对驱动state实际为0，不能只看全局参数。
[历史对照](archive/latency-20261013.md#board-side-isolation-and-completed-frame-mode)保留逐轮数据、无效off尝试、连续A/B/A和未验边界。
