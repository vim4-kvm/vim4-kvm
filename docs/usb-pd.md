# USB-C 开机协商

主线KVM使用内核TCPM管理PD；未启用控制器的旧内核保留有限开机交接。
地址、协议边界与选项以[Linux 工具](../tools/usb-pd-init.c)、[板级模块](../board/vim4pd.py)及[服务](../board/vim4-kvm-pd.service)为准。
导航：[操作](#旧内核操作顺序)、[状态](#供电信息)、[边界](#边界与未验范围)。

内核 TCPM 部署及实测边界见[开机 PD](bringup/2026-11-04-boot-pd-tcpm.md)。
设备树启用 FUSB302 时，板级服务须退出旧协商路径，即使驱动还在等待 probe；
不能因暂时没有 Type-C 端口就回退到原始 I²C 工具。该工具也拒绝已实例化的
内核设备，查询转用 Type-C / power_supply sysfs。未启用控制器的旧内核保持下述路径。

## 旧内核操作顺序

按设备树识别物理控制器，不能跨总线探测；内核已占用或另一个实例持锁即退出。
安装器先部署板级模块再部署 helper，安装和查询不重启 PD 服务或重新协商活动供电。
gadget 描述符由 USB 服务提供，不由 PD 报文提供；服务排序与有限协议处理以实现为准。
成功退出只表示本次开机处理结束，不是持续管理 PD，也不证明创建了新合同。

固件快照只在开机交接读取。仅经校验的已完成合同缺 USB 通信能力时，才运行现有 Linux 修复；
缺失、异常、已有能力或失败回退分别记录原因并跳过。
同次启动失败也不自动重试，避免供电重启循环；查询不主动探测协议状态。
成功合同经同一写入器原子保存历史，保存失败只报错，不触发再次协商。

## 供电信息

管理器优先读取内核TCPM实时合同，按设备树控制器关联同一Type-C端口和power_supply，
只有online、PD模式和sink角色一致时才展示当前协商值。读取失败、尚未probe或退回普通
Type-C时显示未知或未确认，不回退到历史合同；查询不访问控制器寄存器、不重协商。
协商电压/电流来自TCPM的当前工作值，不能把来源最大额度或实际负载电流混为一谈。
管理器与板级读取模块须配套部署；较旧板级模块仍走旧内核的历史读取路径。

只读状态不读取清零中断或 FIFO，不改配置。VBUS 存在不是电压实测，
不能判断 USB-C 或 VIN 哪一路供整板；协商额度不是实际电流或功耗。
Linux 开机合同、固件快照和不同 boot 的历史合同分开，不能让未确认的新状态覆盖旧记录。
损坏、不完整或同次启动的历史不展示；固件回退下沿用历史必须明确标注时间和来源，
不能包装成本次有效合同。详情保留独立错误，不新增 PD 报文。
PDO 是来源额定能力，RDO 才是请求合同；无法确认的 V/A 不拼造。
Battery 与 Variable 不能按 Fixed 解释，Rp 默认档也不能换算成未经确认的电流。

历史与持久化的操作证据见[热重启卡片](bringup/2026-10-22-pd-warm-carryover.md)
和[手动协商](bringup/2026-10-22-pd-manual-contract.md)。
界面数据字段和优先级以板级模块及 manager 消费者为准。

## 边界与未验范围

旧Linux工具仅接管已由启动固件配置的sink，不切电源角色，不向未知控制器写入。
请求仅限实现允许的低压固定供电，电流受源能力限制；
I²C、发送、拒绝或硬复位均报错，不建立自动重试服务。NCM 地址和路由不属本服务。
不保证运行时拔插、主机睡眠或后续 PD reset 恢复；单线供电拔线会断电。
UDC configured 不证明有效 PD 合同。

固件曾只被动等待能力，不能由日志推断此前有合同或 Mac 保存的状态。
主机复现还发现乱序中断、Soft_Reset 和合同后服务缺口；
主动查询本身不要求断电，但对端仍可能硬复位，仅禁本端硬复位不足以保障供电。
[热重启审查](bringup/2026-10-22-pd-warmboot-audit.md)因此保留只读交接。
[Request 候选](bringup/2026-10-22-uboot-pd-request.md)虽通过主机测试和构建，尚未刷写，
不能把限压修正当作完整接管或 HID 验收。

[固件双内核窗口](bringup/2026-10-22-pd-firmware-deploy.md)只证明超时回退快照和启动；
未验真实固件成功合同或完整能力列表。
[正式保留窗口](bringup/2026-10-22-edge-7-3-final-retained.md)验证了回退跳过，
未实板覆盖有效合同缺 USB comm 的修复分支、已有能力分支和插拔。
协议测试见[请求边界夹具](../tests/pd-request.c)，模拟通过不能替代这些硬件结果。
