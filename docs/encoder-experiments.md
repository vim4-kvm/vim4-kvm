# 编码可靠性与关键帧实验（2026-10-13）

源码：NanoKVM-Pro `970f4f9`、gst-plugin-venc `2212f99`。
开发包 `1.0.3+vim4.20261013.3` 已部署，内核为 `5.15.137-vim4kvm`。
包在提交前用 `--allow-dirty` 构建，sources.json 保留当时的源码摘要和脏状态；
不是已发布的正式镜像。锁定清单引用这两个提交，发布清单前须先推送子仓库。

## 已启用的修复

- 按实际加载插件的 framerate 属性范围传参，旧插件不支持的值不传，记录降级警告。
- 每 500ms 检查 HDMI 帧率；连续三次有效且一致的新预算触发重建，未知读数不触发。
  重建沿用原有的一秒重试间隔，切换会短暂停顿，不是无缝动态码率更新。
- VIM4 不再设置流线程的单核 affinity，避免 Go 解锁线程后遗留绑定。
- 原 UI、持久化视频配置和正常编码默认值不变。

隔离构建执行了主仓库与部署 Python 测试、PD 检查、VIM4/上游 Go 测试和构建、
前端构建、sudoers 检查；组件包校验通过。上板 dpkg 文件校验、服务与 USB 枚举通过。

## 硬件验证

当前 HDMI 桌面画面、3840×2160、约 60Hz；不是固定回放的高运动测试片。

| 检查 | 结果 |
|---|---|
| 原厂插件降级 | 实际映射系统目录的旧 libgstamlvenc.so，framerate 上限 30；出现预期警告，Chrome 15s 解码 900 帧，零丢帧/丢包 |
| 修复后的默认配置 | 双 viewer 分别约 60.03/59.98fps，均零丢帧/丢包（25s/15s） |
| 帧率监控 | 通过服务私有 mount namespace 模拟未知→60→30，记录两次预算重建，WebRTC 连接保持且画面恢复 |
| 切换采样 | 25s 解码 1351 帧，零丢帧/丢包；平均约 54fps，包含两次重建停顿，不能当稳态性能 |
| affinity | 重启后的 NanoKVM 21 个线程允许 CPU 0–7 |

旧插件降级先在 `.2` 包验证；`.3` 增加实验环境变量入口、预算重建日志和 affinity 修复。
模拟帧率只验证应用控制流程，没有实际切换 HDMI 源的时序或分辨率。

## QP 和行刷新：保留为实验选项

`amvenc.h` 定义 qp_mode=1 使用自定义 QP 范围；插件新增 `i-qp-min`，
默认 -1 保留厂商行为。`intra-refresh-rows` 默认 0，正值映射行刷新模式及行数。
两个属性只在启动前设置。应用可通过临时 service 环境变量测试；操作见
[VIDEO.md](../NanoKVM-Pro/deploy/vim4/VIDEO.md) 和
[插件说明](../gst-plugin-venc/VIM4.md)。

停止应用后，按顺序对同一 HDMI 输入运行各 720 帧，设置 12000 Kbps、60fps 预算。
下面是编码输出到 Python appsink 的观测，不包含网络和浏览器，也非严格同步回放。
保存 H264 的四组均经 ffmpeg -xerror 解码通过。

| 配置 | 关键帧大小（十进制 KB） | 到达间隔 p99 / 最大值 ms | 实际 Mbps |
|---|---|---|---|
| GOP120，默认 QP | 首帧293；周期帧333–565 | 17.31 / 22.58 | 1.70 |
| GOP120，I QP≥34 | 首帧240；周期帧约115 | 17.07 / 17.56 | 0.52 |
| GOP120，I QP≥40 | 首帧150；周期帧约65 | 16.98 / 17.19 | 0.34 |
| GOP1000，刷新3行，主动请求 IDR | 308、355 | 17.02 / 20.01 | 4.28 |
| GOP1000，无刷新，主动请求 IDR | 308、514 | 17.01 / 22.84 | 0.52 |

两组长 GOP 都在第 360 帧产生请求的关键帧。周期 IDR 减少不能单独证明行刷新的
收益：长 GOP 本身也减少 IDR；刷新组码率显著增加。尚未检查码流内部的刷新覆盖、
恢复点 SEI 或实际丢包恢复。

QP34 的 Chrome 单 viewer 测试为 15s/900 帧、零丢帧/丢包，但尚未定量验证文字画质。
行刷新双 viewer 中，第一个约60.07fps/零丢帧，第二个约59.11fps/14帧丢帧；均零丢包。
正常配置对照没有丢帧。这一轮不足以确定原因，不能据此批准行刷新默认启用。

最终移除了临时 service override 和模拟读数，恢复默认 QP、GOP120、无行刷新。
没有修改内核或开启 sendmmsg。没有端到端延迟、高运动负载或 Safari 的新验证结论。
