# 代码与协作规范

- 项目目标是 7.x 在整颗 T7 上达到厂商 5.15 的能力且性能不低于它（同板对照测量），不止 KVM 路径。
  实现进入 DRM/KMS、V4L2、ASoC、genpd 等标准框架；绕过能力的安全网只能临时存在，并写明计划中的真正实现。
  做不到的项（闭源固件、授权、厂商私有 ABI）写明原因，不静默跳过。5.15 行为本身有错时按规范和主线做对，
  并在结果中说明 5.15 做了什么、错在哪、7.x 怎么做。
- 显示输出须与 VDIN 采集共存（桌面或透传），并支持 HDMI 音频；显示驱动不能假设独占 VPU。
- 在官方源码基线上修改，保留原作者、上游历史与许可证。第三方修改逐项审查，不默认其正确。
- 移植代码和提交信息不添加来源叙述（如 ported from、cherry picked from）；原作者字段、版权与 MODULE_AUTHOR 保持原样。
- 保留 NanoKVM 原界面、API 和业务实现。VIM4 差异优先隔离在 build tag、硬件适配和部署配置中，共享代码只做必要修改。
- 使用清晰命名、显式数据流和小而专一的函数。遵循既有架构，不为假设需求增加抽象。
- 未连接的 ATX、屏幕等硬件显示未配置，不映射到无关 GPIO。
- 遵循当前用户授权，自主完成常规实施和验证；保留其他任务的改动，只提交自己确认的文件。提交与推送分别依据授权。
- 不修改 git 配置和提交身份，本机身份由 ~/.gitconfig 的 includeIf 提供。不改变 Ubuntu 密码和既定本地认证设置。
- 板子测试前确认没有其他任务占用硬件或停启服务；独占测试先协调，不能中断他人测量。
- 生产改动与部署依赖必须入对应仓库，以便制作可复现镜像。上板关键发现按 [上板记录索引](bringup/README.md) 的约定新建条目。
- 测试覆盖真实回归、边界和生命周期，避免仅复述实现。执行子系统所需构建与验证；通过后仅因新改动、失败或未解决风险扩大检查。
- 性能结论附版本、配置、负载、测量端点和记录位置。静态画面结果不能替代运动场景或端到端延迟。
- 新主线内核release用 `<上游版本>-vim4-<UTC打包日YYYYMMDD>`，同日后续构建追加`.2`、`.3`；
  在packaging/kernel/sources.toml的package节记录日期、构建序号、计划tag，kernel节固定源码SHA。
  正式部署验收后在该内核源码SHA上创建`v<release>` tag；本地提交/tag与push分别授权。
  已验收旧release和配置不追改，新构建配置的CONFIG_LOCALVERSION置空，由build.sh显式传LOCALVERSION。
- 明确报告未运行、受干扰和待验证的部分。历史记录不是当前通过证明。
- 注释说明非显然的原因与约束。教训落实到脚本和规范，错题本不能替代实现防护。

## 上板与测试

- 离线优先：先完成实现和离线测试，把「需上板验证」的项汇总后批量占板。不中断进行中的板窗口。
- 只在实际操作板子时持有板锁，构建期间释放；用预先写好的无人值守脚本，单次目标 15 分钟、上限 30 分钟，
  一个任务合计占板不超过 30 分钟；失败立即退出，离线分析。细则见 [占板时间最短化](board-window.md#占板时间最短化)。
- 不测音频（只确认音频服务正常），除非用户要求。稳定性监测默认 10 分钟。
- 候选验收通过就在同一窗口设为默认并保留，不写回滚脚本、不额外备份；只有失败才恢复。
  需要用户目视时直接部署到所有 KVM 应用和 UU 会话，不做临时预览。
- 自己复现和确认：用发送端计数、日志、应用 API 和 Mac 上的自动化；只有接线等物理操作或最终目视验收才找用户，合并为一次请求。
- 被控机是 Mac mini M6。测试准备可经 One-KVM MCP 操作它：先截图、最少点击、避免裸 Shift 和输入法、结束后恢复改过的设置。
  普通自动化测试不发 HID；绝不向开发机 Mac mini M4 注入 HID。
- M6 是唯一 HDMI 源，无法输出真实 HLG、隔行、像素重复、真 12bit 和 VRR；需要这些格式验收的工作不排上板，只做主机测试。
- 板子 HDMI OUT 接 Mac 上的 USB 采集卡，它会压缩颜色：颜色以寄存器回读对照 5.15 为准，采集卡只做相对比较和粗错检查。
- 开发板流程全自动，不弹密码（已 enroll 免密 sudo，见 [默认账户](hardware.md#默认账户开发环境)）；开发便利不进入软件包和镜像。
- 验证通过并已提交的工作直接 push（只推自己的提交）；GitHub Release、上游补丁等发布行为先问用户。

## 审查

使用模型：单块 VIM4 开发板，唯一 HDMI 源为 Mac mini M6；开发者或 agent 在 Mac / OrbStack VM
运行工具，板上使用默认配置，单人使用。One-KVM 默认关闭的功能不算真实使用路径。
管理面板主要在局域网，偶尔经 Tailscale 暴露到公网：登录按公网标准设计，不留通往 KVM 应用的未认证网络路径；
MCP、VNC、RTSP、UU 等非网页入口保留各自密钥。
发现按以下规则分流，不打分：

- fix：真实使用路径会发生，写明谁在什么操作下触发，修复并验证。
- simplify：修法是删代码或更简单，不论频率都做。
- file：罕见但值得记，写入 [issue 清单](issues.md)，不改代码。
- drop：对抗性输入、自作的错误配置，或对后来者没有信息量，只在审查结果里提一次。
