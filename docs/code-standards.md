# 代码与协作规范

- 7.x须覆盖整颗T7，能力和同板性能不低于5.15，不限KVM。
- 实现用DRM/KMS、V4L2、ASoC、genpd等标准框架，安全网仅临时保留并注明真正实现计划。
- 因固件、授权或私有ABI无法实现的项须说明原因，不能静默跳过。
- 5.15有错时按规范和主线实现，并报告原行为、错误及新做法。
- 显示桌面或透传须与VDIN共存，支持HDMI音频，不能独占VPU。
- 基于官方源码修改，保留原作者、上游历史和许可证，逐项审查第三方修改。
- 代码和提交不加来源叙述，作者字段、版权和MODULE_AUTHOR不变。
- 保留NanoKVM界面、API和业务，VIM4差异优先隔离到build tag、硬件适配或部署配置，仅必要时改共享代码。
- 命名清晰，数据流显式，函数职责单一，遵循既有架构，不为假设需求增加抽象。
- 未连接的硬件显示为未配置，不映射到无关GPIO。
- 自主完成已授权的实施、验证和提交，保留他人改动，只提交确认属己的文件。
- 不修改git配置、提交身份、Ubuntu密码或既定本地认证。
- 事实以代码为准：版本、SHA、路径、端口、参数、默认值、选项、阈值和清单应链接配置、源码符号、脚本头或--help，不在文档复述。
- 文档写理由、约束、顺序、教训和未验边界，与代码冲突时改文档，不据文档改代码。
- 生产改动及部署依赖须入对应仓库以复现镜像，关键上板发现按[索引](bringup/README.md)记录。
- 测试覆盖真实回归、边界和生命周期，不复述实现。
- 完成子系统构建和验证，通过后仅因新改动、失败或未解风险扩大检查。
- 性能结论须附版本、配置、负载、测量端点和记录，静态画面不能替代运动场景或端到端延迟。
- 报告未运行、受干扰和待验证项，历史记录不能证明当前通过。
- 注释说明非显然理由和约束，教训落实到脚本和规范，不能只记错题。
- 主线版本按[源码锁](../packaging/kernel/sources.toml)维护，打包日用UTC。
- 本地tag不等于可以推送tag，推送tag先问用户。
- 已验收release和配置不追改，新配置不硬编码release，由[构建脚本](../packaging/kernel/build.sh)注入。

## 上板与测试

- 实现和离线测试完成后，汇总待验项再批量占板，不打断板窗口。
- 测试前确认无人占硬件或停启服务，独占测试先协调，不能中断他人测量。
- 只在实际操作板子时持板锁，构建期间释放板锁。
- 预写无人值守脚本，单次目标15分钟、上限30分钟，每任务累计不超过30分钟，失败立即退出并离线分析，见[细则](board-window.md#占板时间最短化)。
- 除非用户要求，否则不测音频，只确认音频服务正常，稳定性监测默认10分钟。
- 候选验收后在同一窗口设为默认并保留，不写回滚脚本或额外备份，仅失败时恢复。
- 目视验收直接部署全部KVM应用和UU会话，不做临时预览。
- 用发送端计数、日志、API和Mac自动化自行复现确认，只把物理操作和最终目视合并成一次用户请求。
- 被控机M6可经One-KVM MCP准备测试，先截图、最少点击、避免裸Shift和输入法，结束后恢复设置。
- 普通自动化不发HID，绝不向开发机M4注入HID。
- M6无法输出真实HLG、隔行、像素重复、真12bit或VRR，验收仅做主机测试，不排上板。
- HDMI OUT接Mac USB采集卡会压缩颜色，颜色以寄存器回读对照5.15为准，卡仅作相对比较和粗错检查。
- 板上流程全自动且不弹密码，见[免密sudo](hardware.md#默认账户开发环境)，开发便利不进包或镜像。
- 验证并提交后直接push，只推自己的提交，Release和上游补丁等发布先问用户。

## 审查

使用单块VIM4，唯一HDMI源为Mac mini M6，开发者或agent在Mac或OrbStack VM跑工具，板用默认配置且单人使用。
One-KVM默认关闭的功能不算真实路径。
面板主要在局域网，偶经Tailscale暴露公网，登录须按公网标准，不留到KVM的未认证网络路径，MCP、VNC、RTSP和UU各保留密钥。
发现按以下规则分流，不打分：

- fix：写明真实路径中谁在什么操作下触发，修复并验证。
- simplify：删代码或更简单就能修，不论频率都做。
- file：罕见但值得记，写入[issues](issues.md)，不改代码。
- drop：对抗输入、自造错误配置或对后来者无信息量，仅在审查结果提一次。
