# Ubuntu 组件构建与安装合同

本页管用户态组件包，不是可刷入镜像；镜像见[镜像流程](ubuntu-image.md)。
构建和验证不挂载板设备、不 SSH、不停启板服务。
导航：[输入](#固定输入)、[使用](#使用)、[安装](#包和安装边界)、[更新](#单独发布与网页更新)、[PiKVM](#pikvm-组件)。

## 固定输入

基础镜像、APT 快照、工具链和下载摘要分别以[容器配方](../packaging/ubuntu/Dockerfile)
与[下载锁](../packaging/ubuntu/downloads.lock.json)为准；厂商包只解包，不执行安装脚本，
也不从工作板抓二进制。历史 Release 可过期不等于跳过签名校验。
快照保留有期限，长期发布须保存镜像和输入，固定地址不替代存档。

源码来自实际工作树，制品收据记录提交、脏状态、内容摘要和实际 builder。
开发构建允许脏源码并标记，正式版本拒绝；不能用手填版本冒充正式构建。
版本生成、排序和组件清单以[构建入口](../tools/ubuntu-build.py)为准，不手抄示例版本。
离线仅有本地 tags 时部署前先确认正式基线；失败目录也占用开发序号，不清空复用。
跨工作区部署开发包时，用 `package --after-version` 指定目标板上较新的已安装版本，
避免本地缺少历史构建目录时生成降级包；安装器仍独立执行禁止降级检查。

## 使用

按构建入口帮助依次准备 environment、package、verify。
源码只读挂载后复制到容器工作目录，不让 Mac 依赖和旧编译产物进入 Linux 构建。
输出拒绝覆盖，失败保留，新尝试用新目录。输入摘要变化必须重建环境，不能信同名镜像标签。
verify 复用收据所记保留镜像，package、verify 和 assemble 使用同一实际输出版本，
不隐式选旧包。APT 索引不完整就停止。
Cargo 下载缓存在独立 Docker volume 中复用，仍由锁文件及 Cargo 校验摘要；
应用源码和编译产物继续在每次打包容器中独立构建。

verify 在临时容器核对校验和、架构、动态依赖、sudoers、网页、首次配置及升级保留；
不把[验证脚本](../packaging/ubuntu/verify.sh)当宿主安装器。
还须核对音频启动顺序、预处理路由与依赖，防止当前板正常而新包静音。
离线测试与构建的具体集合由配方执行，调用者保存完整日志。
通过只证明构建和隔离安装范围，不证明实板采集、编码、PD 或端到端性能；
现有隔离验证暴露过测试插件缺失和上游链接桩步骤，已补齐，不推广成启动验收。

## 包和安装边界

包内容、依赖和能力标识以[打包配方](../packaging/ubuntu/)为准。
应用新增能力须先部署匹配平台依赖；新服务端与特权 helper、sudoers 成套安装。
这些包依赖既有 Khadas 系统、用户、固件、内核和厂商服务，不把普通 Ubuntu 容器变成可启动板。
外部运行库不因锁入下载清单就获准随组件重新分发。

包不覆盖管理员在系统配置目录的手工 unit 或 drop-in，迁移前须检查覆盖关系。
postinst 不操作 configfs、I²C、网络或密码，不自动启用、重启服务；
首次配置仅在配置缺失时写默认，升级保留用户文件。镜像阶段显式设置服务启用与冲突。
不能运行在线 board 安装脚本冒充离线安装。

应用资源和用户数据分开，缺引导资源须验证失败；既有虚拟盘不重新格式化。
[介质检查器](../tools/one-kvm-drive-check.mjs)只在独占且授权时初始化或挂载，
结束保留盘、删除本次测试文件。
postinst 与更新助手的 sync、helper 比较和 sudoers 校验不能保证 dpkg 断电原子性，
失败仍需检查并恢复完整安装。

根文件系统持久化策略以[策略工具](../tools/rootfs-policy.py)为准，
自定义参数要求先审查，不能静默覆盖；重启后确认实际挂载。
保存源码、包版本、外部下载及摘要收据，尚未证明所有工具链产物逐字节可复现。
发布前清单引用的子仓库提交必须可取得，构建成功不扩大发布授权。

## 单独发布与网页更新

各应用更新协议和包映射以[feeds](../packaging/ubuntu/feeds.py)及[工作流](../.github/workflows/)为准。
网页更新仅替换自身应用包；APT 预演若需新增或升级平台包则拒绝，先完整部署依赖。
涉及共享介质 API 的组合部署不走单应用更新，镜像集成和独立发布的组件集合也不同。

CI 构建与发布权限分开，普通构建不访问板子；发布不代表实机回归。
其他仓库依清单取源码，本仓库按触发提交；不要混入另一仓库尚未发布组件。
缓存随配方和锁失效，首次环境仍需完整下载。镜像 workflow 的 artifact 与公开发布分开，
可刷候选仍需独立实板启动验证。

## PiKVM 组件

先基础 builder，再专用环境、打包和验证，按[PiKVM 配方](../packaging/ubuntu/pikvm/)的固定依赖执行。
Python 与 nginx 私有路径隔离，Janus 使用锁定上游及对应网页补丁。
安装不切换应用，镜像显式选择集成包和默认应用，不把通用 all 当作包含全部 PiKVM。
隔离验证须有真实 Janus 插件会话、配置校验与认证文件升级保留。

上板按[烟测工具](../tools/pikvm-smoke.mjs)帮助选择功能，音频和 HID 只在明确授权范围启用。
介质夹具及认证变量以脚本要求为准；独占板子、USB 主机和 HDMI 源，
挂载介质时须验证应用切换保护。构建通过不能替代真实主机读盘或音视频验收。
