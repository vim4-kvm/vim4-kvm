# USB 与供电

改 PD 协商读 [USB-C 协商](../usb-pd.md)；查接口和接线读 [硬件](../hardware.md)；
改某个应用的 HID 或介质对接读该应用的 VIM4.md（见 [应用](application.md)）。

键鼠输入延迟、长按和 Mac 滚轮方向的测试入口见 [输入验证](../input-latency.md)。

板级 gadget 服务拥有 configfs，PD 服务负责开机有限协商。
应用使用 hidg0/1/2 对应键盘、绝对鼠标、相对鼠标，不重新创建 gadget。
虚拟介质与板级预设协调，不部署上游设备专用 USB 脚本。

One-KVM 的限定助手可暂时修改这个 gadget 的描述符与功能链接，并按需创建
hidg3 多媒体键、ECM/RNDIS 网络实例；不删除原有 HID 实例。应用停用后由
ExecStopPost 恢复原始配置，详情见 [One-KVM 适配](../../One-KVM/VIM4.md#hid-功能配置)。
最多 5 个 IN 端点；网卡占两个，其余每个 HID、UAC2、磁盘各占一个。

虚拟磁盘挂载状态属于板级共享 LUN，不随当前 KVM 名称变化。管理面板的虚拟介质页
显示实际镜像文件名、只读/可写与 USB 连接状态，KVM 界面页仅显示摘要。切换涉及 PiKVM 且仍挂载介质时，
可选择「弹出后继续切换」，在被控电脑安全弹出后由当前页面提交切换，助手再次检查。
取消、离开页面、状态未知、连接中断、应用改变或等待超过 5 分钟都会结束等待。
不提供强制弹出；仅卸载卷不等于主机发送 SCSI eject。
NanoKVM 启动不再根据旧 enabled 标记自动重新连接数据盘；镜像文件保留，需用户主动连接。

管理器还汇总各 KVM 现有 ISO/IMG 镜像与共享数据盘，可选择只读或可写挂载。
ISO 与 JetKVM 限定只读，已有介质时拒绝替换。弹出按钮需先确认主机已停止使用并安全卸载，
遵守主机防弹出锁，不通过 USB 解绑强制移除；完成后保留空存储接口。
One-KVM 的自定义 USB 组合保持不变，端点不足需先调整其 USB 功能。
各应用查询时读取实际 LUN：PiKVM 显示非自有存储的镜像，JetKVM 与 One-KVM 将不是本进程挂载的
介质标为外部介质，并拒绝在应用内替换或弹出，需先在被控电脑安全弹出、再由管理器弹出。
四个应用的镜像列表同时展示所有共享数据盘和其他应用的镜像，按来源分组；
其他应用目录的镜像只读，不能在当前应用中删除。NanoKVM、One-KVM 可将数据盘可写挂载，
JetKVM、PiKVM 只读挂载。NanoKVM 的旧“虚拟磁盘”开关仍对应 `disk.img`。
主机弹出虚拟光盘时内核会清空 LUN，各应用随之清除自身记录。

管理器的「数据盘」页提供 FAT32 多盘创建、卷标、文件上传下载、文件夹、重命名、删除，
以及扩容、完整镜像下载、快照和恢复。挂载中的盘禁止编辑；状态未知时拒绝写入。
只读浏览挂载中的盘不保证与主机缓存一致。文件操作使用 mtools，单文件上限为 4 GiB-1。
现有 `disk.img` 不自动格式化或改变卷标。接口与验证入口见
[管理器说明](../../vim4-manager/README.md#共享数据盘-api)。

各特权助手使用板级 `vim4media` 模块统一目录校验和两把共享介质锁；
长文件操作只持数据盘锁，阻止同一盘被挂载，不占用整个操作期间的全局锁。
发布时先安装包含该模块、mtools、dosfstools 的板级包，再更新应用和管理器。
新板级包提供 `vim4-media-api-1`，应用显式依赖此能力，防止旧平台满足版本号却缺少模块。
网页更新不能代装平台依赖；旧板子需先完成平台组件更新。

PD 不是完整 TCPM；单线供电时拔线会断电。启动枚举通过不等于睡眠唤醒、
运行中重置和 NCM IP 通信通过。改描述符或协商代码后运行相关边界测试，
再验证主机枚举和实际输入，避免干扰其他任务。

## 错题

| 触发条件 / 错误 | 原因与正确做法 | 验证入口 |
|---|---|---|
| 认为 USB-C 供电必须另接 VIN 才能传键鼠 | 本项目已验证开机 PD 协商后单线供电和 HID，不代表所有供电、热插拔场景 | [USB-PD](../usb-pd.md) |
| USB 主机卸载卷后仍不能弹出 PiKVM 镜像 | unmount 不清除 SCSI 防弹出锁；必须 host eject。厂商内核 host eject 不发 configfs inotify，需要在现有轮询中核对 LUN file | kvmd/kvmd/plugins/msd/otg/__init__.py |
| 管理器挂载共享介质后，以为各 KVM 网页都能看到并安全操作 | 实测只有 PiKVM 实时读取 LUN；JetKVM 只在启动时读一次并把他处镜像标成自有存储，One-KVM 从不读取且自身挂载会 forced_eject 他处可写盘。共享资源的状态必须在查询和变更时读取实际 LUN，非本进程挂载的介质只显示不覆盖，特权助手在共享锁内再核对一次；切换四个应用逐一在网页核对，不能只看管理器 | logs/media-crossapp/、kvm/internal/vim4media、One-KVM/src/msd/controller.rs |
| FUSE 镜像做 LUN，后端 NAS 卡住，主机复位整个 USB 设备 | 读写超过主机 SCSI 超时（约 30 秒）主机会复位设备，Mac 随后不再识别存储接口，需 UDC 重新枚举。LUN 后端 I/O 必须在约 8 秒内返回错误；本内核无 forced_eject，模拟拔线用 UDC 解绑 | [NAS 存储与 U 盘](../bringup/2026-10-18-nas-storage-usb-disk.md) |
| 合成 FAT32 + 4 KiB 写入层，主机只读的文件被当作改写 | 数据区起点未按 4 KiB 对齐，块跨簇使相邻文件被标脏。合成卷的 FAT 与数据区按簇对齐；FAT 时间是无时区本地时间，按发起挂载的浏览器偏移换算 | vim4-manager/internal/vfat |
