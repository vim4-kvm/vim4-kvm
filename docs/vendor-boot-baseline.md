# 厂商内核一次性对照启动

本页管保留默认项的一次性启动与恢复；正常往返已验证，硬挂死自动复位未证明。
导航：[准备](#离线生成与下次窗口门禁)、[恢复](#自动返回的边界)、[兼容](#兼容性与风险评估)。
当前默认身份以[主线入口](kernel-mainline.md)为准，不能沿用历史候选或旧 Stock 名称。

## 离线生成与下次窗口门禁

[生成器](../tools/vendor-boot-plan.py)只读本地快照并写新目录，不 stage 或 reboot。
参数与 profile 格式以帮助和源码为准。必须从新清单解析真实链接、固件变量及板型，
不能从另一个内核 cmdline 猜厂商参数，示例不能直接上板。
生成器不验证实际文件存在、构建匹配、分区和硬件参数语义，执行者补齐证明。

1. 取板票后记录当前完整身份、启动文件、运行助手与收据摘要；备份配置及一致的应用数据，
   核对服务和实际输入健康，主机弹出全部虚拟盘。采样前构建全部完成。
2. 核对厂商 Image、initrd、DTB 和全模块同次构建。initrd 包含实际根设备和文件系统支持，
   不混入另一内核模块；对照保留内存、CMA 和供电，不能临时拼 DT 属性。
3. 确认两个内核都能运行同一用户态和各自匹配插件，不降级数据库。
   用当前默认项的同一载荷先验证独立 sysboot 配置及正常复位回默认。
4. 按 plan 给出的路径独占创建小配置，读回哈希并同步文件与目录；
   不改默认、公共链接、登记、固件环境或既有模块目录。
5. 串口捕获日志，只在当次固件 RAM 中选择 plan 命令，不 saveenv、不写开机脚本。
   启动预算内核对实际构建、模块、应用、编码、USB 主机输入；HTTP 就绪不是全兼容。
6. 第一轮立即回进入前基线，核对身份、文件、配置、服务与真实运动画面。
   往返通过后才排性能配对；保留 plan 与日志，不删除厂商产物。
   失败正常重启或外部 RESET，不热解绑网卡和 UDC。

历史路径、实测范围见[短窗口](bringup/2026-10-23-vendor-boot-gpu.md)，
它不替代下一窗口的新清单和恢复目标。原[显示安全网](bringup/2026-10-23-display-m1-safety.md)
的特定 release/PID1 不能直接移用于另一内核。

## 自动返回的边界

读取失败返回可执行复位，panic 的自动重启只覆盖实际进入 panic 的路径。
用户态仍可运行时经串口正常 reboot；串口超时不表示命令退出，不堆叠命令。
早期引导、总线或内核硬挂死需已验证的硬件看门狗或独立 RESET，软件计时器和控制端 finally 不保证恢复。

目前没有可调用执行器覆盖全部硬故障的证明，只允许有人能 RESET 的短窗口；
不生成猜测 GPIO/电源命令，也不为测试改持久看门狗配置。
无人值守需独立供电、启动及失联预算、有限次触发和返回后停止的实际证明。
一次性选择可准备，不等于无人值守自动返回已成立。

## 兼容性与风险评估

模块与 initrd 隔离且保留系统目录符号链接；缺模块即停止，不能借另一 release。
pstore 布局逐内核核对，切换前保存日志，后一次启动可能覆盖旧记录；
无 pstore 不能证明无崩溃，串口是独立证据。

HID 与 CRG 须含[生命周期修复](kernel.md)，旧版重绑定可能 panic。
先停应用释放文件，再整机重启，不在此做重绑定压力；重新枚举后验证真实主机输入。
PD 合同与 UDC 分开判，保持供电拓扑不变，单线供电运行中不能拔线。
网口 carrier 正常也可能不可达，串口保持可用，不靠热重绑恢复。

共享根文件系统不会随内核回退：禁止中途安装升级，恢复服务和应用设置，
D 状态时不覆盖打开的数据库或 WAL，回健康基线再处理。
性能与预算按[基线协议](performance-baseline.md)，
历史操作授权不自动扩展到新窗口。
