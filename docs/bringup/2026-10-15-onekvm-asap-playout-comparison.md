# 2026-10-15：One-KVM 尽快播放策略对照

基于 `e5878e6d` 的隔离源码副本，仅增加视频 playout-delay 0/0 的协商与每帧首包扩展，
保留 H.265 行刷新等编码设置。609 项 Rust 测试与 ARM64 release 构建通过；正式包未替换。
独立临时账户和数据库、18081 端口，顺序占用编码器。

原版/候选各两种编码 90 秒的初测遇到候选 H.265 选择 IPv6，因此补做固定有线的同二进制
协商对照。Chrome 155，4K60/60Mbps，每组 60 秒含 25 秒 HDMI 全屏运动，真实音频轨保留。
浏览器与板端分别核对 codec/SDP 和 UDP 目的地址 `192.168.50.239`；RTP 包头另确认 0/0 确实发送。

末 20 秒缓冲：H.264 默认/0/0 为 32.21/0.50ms，H.265 为 26.31/0.47ms。
解码均约 3.5–3.6ms。四组零统计丢包、丢帧、freeze，解码音频峰值约 0.10。
H.264 帧回调 P99 为 33.4/50.1ms、最大均约 83ms；H.265 P99 均 33.4ms、最大均约 50ms。
低缓冲已有对照证据，但 H.264 尾间隔需重复测量，不能把所有流畅度指标写成改善。
详细方法、二进制哈希与限制见 [延迟差异调查](../kvm-delay-causes.md)。
证据：`logs/onekvm-playout-ab/`，最终结果为 `final-summary.json` 的四组固定有线数据。
