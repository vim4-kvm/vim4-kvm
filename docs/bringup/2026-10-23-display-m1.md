- meson目录内增加固定1080p60 RGB888 primary plane/CRTC/GEM DMA入口，使用真实IRQ，
  在vsync更新OSD1地址；再等一次IRQ后完成事件和释放旧缓冲。超时保留DMA引用并拒绝新提交。
- 专用DT禁用simple-framebuffer和完整native VPU，保留双帧no-map区，显式检查交接合同。
  VDIN以四段资源映射运行；原sysfs/debugfs平台名、采集时钟、仲裁及reset行为保持原合同。
- hdmitx21只读bridge使用厂商SMC读TOP/COR，跳过普通路径的TX/PHY/DDC/音频初始化。
  固定模式不调用普通meson的全局VPU/VPP/VIU/VENC初始化。
- 固件使用ENC2；显示只写OSD地址，不写VENC中断寄存器或VIU mux。
  注册前须100ms内收到两次VIU1中断；connector按固定sink报告connected，尚无物理HPD。
- 候选DT选择只读HDMI PLL provider，连注册和消费者enable都没有PLL写回调；
  普通DT继续使用原provider。仅“不调用set_rate”不足以保证PLL保持不变。

## 临时安装与恢复

首轮窗口持有board/heavy双锁，完成双份备份与文件哈希校验，但打包遗漏
`--framebuffer-console`，runtime注册检测到M0既有 `console=tty0`，报
`FullKvm has custom boot arguments; refusing to replace it`。候选没有启动。
脚本按原备份恢复后正常重启，得到：

```text
BASELINE_RESTORED f483ea42fee88be39ea67c43478638be67334d6e
BASELINE_HID_VERIFIED
```

实际HID日志包含 `keyboardDown=1`、`keyboardUp=1`、绝对/相对鼠标、点击和滚轮通过；
只读查询为one-kvm/manager均active、UDC configured。第二轮保留完全相同的tty0参数，
仅修正临时包注册选项，不更改内核、DT或正式运行时锁。

第二轮成功启动首次候选，`CRITICAL_HEALTH_VERIFIED 38057ca97e2f9eed58abb0fe2da54e1589ce45bc`。
驱动未注册，modetest查询失败，因只读preflight记录到：

```text
boot OSD ctrl=0x72ff005 format=0x408700 VENC totals=1715/524
boot TX HPD=0x2 active=0x4380780 TMDS=0x0 (SMC read-only)
Firmware display contract does not match
TX boot mode is not connected 1080p
```

其中旧日志里的HPD/TMDS标签解释不成立。串口U-Boot明确打印 `enc_idx: 2`；
厂商 `hdmitx21/hw/reg_ops.c:get_enc_paddr()` 对ENC2的0x1b00–0x1cff加0x800 word。
HPD实际由 `hdmi_tx_hw.c:hdmitx21_hpd_hw_op()` 读取GPIOW15，TOP_STAT0不提供原假设。
`mesont7_drm.dtsi`的VIU1 IRQ为SPI197，`meson_vpu.c:am_meson_vpu_irq()`及T7 OSD
handler不使用旧VENC INTFLAG/INTCTRL。后续修正据此采用ENC2只读窗口和原有edge IRQ，
增加probe中断到达检查；未改PLL、mux或GPIO，也没有为通过测试强开中断。

第二轮结束同样得到 `BASELINE_RESTORED f483ea42fee88be39ea67c43478638be67334d6e`
和 `BASELINE_HID_VERIFIED`。没有DRM图案、page flip或候选KVM共存通过证据，
不能把该轮的服务健康检查当作显示里程碑通过。
