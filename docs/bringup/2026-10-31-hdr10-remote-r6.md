## 真十位与Panfrost短样本

独占停One-KVM后，经VDIN MMAP四缓冲抓两帧AMLY；私有`vim4amlysrc`抓两帧P010。
低位检查在离线诊断读回中执行，产品转换仍为dma-buf Vulkan，无CPU转换后备。

| 项目 | 本次结果 |

| AMLY Y0低两位0/1/2/3计数 | 450280 / 2828251 / 305577 / 563092（每五字节采一个Y0） |
| P010 | 两帧49,766,400字节；stride=7680，UV offset=16,588,800 |
| P010首帧Y低两位0/1/2/3计数 | 896306 / 5657393 / 613458 / 1127243 |
| AMLY SHA256 | 4e289133f26b62e50bef5c87b38b5c03e5b6141c8123ebd0b2cc73a072414292 |
| P010 SHA256 | dcee213b9e820765d7de3a59eec996215550a8efd5a8a24f2c3d4bf16a354d25 |

GPU使用私有Mesa26.2.6 PanVK、Mali-G52、显式panfrost ICD；管线为
`vim4amlysrc num-buffers=300 ! fakesink sync=false`。完成300帧，启动到EOS5.0999秒；
source pad的299个单调时间间隔为60.1304fps、p99=19.3755ms、max=19.4737ms。
这是约五秒静态桌面的GPU输出端点，包含输入节奏，不是GPU kernel耗时、显示p99或端到端延迟。
当时VM另有heavy构建，未标记为无干扰性能验收；未测GPU占用，结束后250MHz不是负载频率。

[measure-gpu.py](../../packaging/hdr10/measure-gpu.py)保留同一无CPU像素读回测法，
额外每秒保存自身DRM fdinfo和频率。驱动无engine计数时报告缺失，不填0；
相同drm-client-id去重后才可按驱动计数单位求delta/elapsed，kbase亦须用其已验证统计接口。
后续固定相同源/分辨率/帧数/ICD/测量端点，对照5.15和kbase uhd5，不等待它才整理本轮证据。

## 编码阻塞、修复与余项

内核ENUM_FMT列出P010，S_FMT接受3840×2160、stride7680、size24,883,200。
但gst-inspect的v4l2h265enc sink只列八位格式；日志明确
`Unsupported fourcc 0x30313050 P010`，原生管线在link阶段失败，未产生可验收HEVC。
原因是原补丁已有fourcc→video-format映射，却遗漏
`gst_v4l2_object_v4l2fourcc_to_bare_struct()`的raw格式分支。

修复加入该分支，并在私有插件构建前编译实际映射/caps函数：P010源必须可交集协商，
实际GstVideoInfo必须为UHD十位布局；NV12不能误交集，AMLY不能获得标准raw caps。
新增[test_gstreamer_p010.py](../../packaging/kernel-edge/test_gstreamer_p010.py)。
重建插件SHA256为`a4f2b009deb8ffed68af674a420df299e19775d7698a18c39b8d97c11f399f1f`。
仅重编用户态插件；新RAM归档使用kbase的原样payload-id工具与独立hdr10 namespace，
不复用已上板的e1028…旧目录，不重编内核或One-KVM。

仍未通过：实际Main10 SPS/VUI/SEI与5.15比较、网页HDR解码4K60及其p99、UU实收、
原生↔HDR2产品输出往返、原生期间SDR截图。M6源SDR↔PQ与映射截图能恢复，
不能替代这些原生产品门禁。按用户顺序，本轮不进入后三款应用实现。
