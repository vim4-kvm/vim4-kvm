主仓 `uhd1.config` 增加 `CONFIG_DRM_MESON_T7_HANDOFF=y`，使后续统一构建包含 M1；
`package-final.py` 增加显式 `--dtb amlogic-t7-a311d2-khadas-vim4-display-m1.dtb`，
默认 profile 不变。M1 打包会拒绝缺失内建驱动、simpledrm/VPU 未禁用或误用 M2
兼容项的 DT。离线测试注入上述错误；Linux 对本轮真实 M1 config/DTB 的检查通过。
联合部署需显式选择 M1 DT 和同次完整模块，不把 M2 DT 混入这次正式部署。

M1 实际模式定义在 `drivers/gpu/drm/meson/meson_t7_handoff.h`：

```text
1920x1080, clock=148500 kHz, htotal=2200, vtotal=1125
148500000 / (2200 * 1125) = 60 Hz
```

probe 读回 ENC2 的 `MAX_PXCNT=2199`、`MAX_LNCNT=1124`，匹配该固定时序。
它不是 1080p30。IRQ 第一次写新地址并推进 written，下一次才把 applied 推进；
提交线程等待 applied 后释放旧 framebuffer、发 flip event，因此连续提交每两个
vblank 完成一次，实测约 29.97Hz。由此推算 IRQ 约 59.94Hz，但本轮未直接测像素 PLL，
不把固定 mode 的名义 60Hz 当成实测时钟精度。

这是 M1 保守的 DMA 退休策略，未改成单次 vblank 后立即释放旧缓冲。M2 需先确认
OSD 寄存器锁存点/RDMA completion，再让提交每个 vblank 推进、按硬件完成证据退休旧帧；
超时仍保留可能被 DMA 使用的内存。离线加速计数不能证明物理输出达到 60 flips/s。

M2 DT 是 `amlogic-t7-a311d2-khadas-vim4-display-m2.dtb`。monitor 仍保留固件
PLL/PHY/VENC/VPP，不重设时钟，不宣告 audio codec。EDID 的 4K mode 可以读到，
但当前 mode_valid/CRTC 仍只接受 1080p60；这不等于支持 4K 切换。
HPD 反映真实 GPIO，消抖采用工作队列轮询，尚未接 GPIO 中断；拔插上板尚未验证。
重新插入若 sink 需要重新设置 TX/PHY，monitor 不能保证画面恢复。

RGB32 只对新 `amlogic,t7-display-linear` 兼容项开启；M1 兼容项仍只有 RGB888。
GEM DMA PRIME import 要求整个缓冲在设备 DMA 地址空间连续、落在 32 位窗口，
非线性 modifier 被明确拒绝。`prepare_fb` 收集生产者 fence，由 DRM atomic helper
在提交前等待。它没有 CPU 拷贝路径，但 Panfrost 导出的任意 BO 不保证都能满足连续性，
仅请求 linear 不能保证物理连续。优先由 KMS GEM DMA/CMA 分配 scanout BO，导出
dma-buf 后交 Panfrost 导入并渲染，再显示同一个 BO；这条路径不需要 CPU copy。
若由 GPU 分配并导出，则必须另外满足显示设备的 DMA 连续性约束，不能只看 modifier。
AFBC、散页无法映射成连续 DMA 的 BO 和 YUV 直通仍不支持。
本轮没有真实 GPU dma-buf 导入/scanout/隐式 fence 上板证据。

## 厂商核对与后续实现顺序

固定厂商源码为 VM `~/src/linux/common_drivers`（`4cfb128d36f8`）；
资源明细及最初差异见[硬件审查](2026-10-23-display-hardware-audit.md)。本轮逐项核对：

- `hdmitx21/hw/reg_ops.c:75–116`：SMC 读/写与 32/8 位宽 ABI。
- `hdmitx21/hw/hdmi_tx_hw.c:197–214`：T7 HPD 为 GPIOW15，不能用 TOP_STAT0 bit0。
  主线 pinctrl 的 GPIO 寄存器基址 `fe0040c0` 加 W 输入偏移 `0x60*4`，
  等于厂商 PADCTRL `fe004000 + 0x90*4`；使用 gpiod，不增加私有 devmem。
- `hdmitx21/hw/hdmi_tx_ddc.c`：AON DDC FIFO（0x00a）、segment/offset、16 字节 FIFO、
  状态和错误恢复；EDID 校验/扩展解析使用 DRM，不再写私有 EDID parser。
- `osd/osd_fb.c:168–213`、`osd/osd_hw.c:3544–3565,8317–8357`：RGB24/32
  block/map 编码、16 字节地址/stride 单位、32 字节 stride 对齐和 vsync 更新。
- `hdmitx21/hw/hw_t7.c`、`hw_clk.c`、`enc_cfg_hw.c`：PLL/PHY、ENC 索引与时序；
  它们不能被现有 `meson_venc.c` 的 ENC0 初始化直接替代。

下一阶段按以下依赖实现，避免把尚未审完的全 VPU 初始化直接放进 M2 DT：

1. **共享资源及原生模式切换**：扩展 meson-drm 的 T7 资源访问层；保留 VDIN0、
   `VPU_SW_RESET` bit26、`0x27a2/0x27a3` 写仲裁和 VDIN top 控制的归属。
   共享字通过单一 regmap/掩码仲裁访问，禁止整字覆盖或显示关闭时复位整个 VPU。
   固定 ENC2/VIU1，分离 CRTC timing、VPP 窗口、OSD 窗口和 hdmitx21 bridge 状态。
   现有 `meson_venc.c` 会切 ENC0，T7 表还把 VIC96/97 复用 25/30Hz 时序，
   没有完成 4K50/60 对照，不能宣称这张表已支持 4K60。
2. **CCF/PHY 与 4K**：只给 TX 独占 pixel PLL/PHY 设置速率，不降低 RX/VDIN 要求的
   VPU/VAPB 频率；先 720p60/1080p60/2160p30 RGB8，再在 sink SCDC 能力匹配时
   接 2160p60、TMDS scrambling/1:40。PLL 锁定失败返回错误并保留安全状态，
   不照搬固定 1080p mode 的数值。FRL/DSC/VRR/HDCP 不在首批实现范围。
3. **HDMI TX 音频**：保留 `VIM4HDMIRX`/TODDR_A 原采集声卡，另建 FRDDR→TDM→
   TOHDMITX→DRM hdmi-codec 播放声卡。不恢复旧 sound 节点里全局 assigned-clock
   设置，不抢 RX audio PLL/FRHDMIRX；先核对 FRDDR/TDM 所选实例、MCLK/BCLK/LRCLK
   和时钟父源，再接 ELD、ACR N/CTS、Audio InfoFrame、静音与模式变化。
   已提交 codec 回调修正只是播放链的一部分，当前没有可用 TX ALSA PCM 交付。
4. **逐 vblank 翻页与直通**：核对 OSD/RDMA 锁存完成后实现每帧流水提交，保留
   buffer/fence 引用到实际退休。先证明 RGB32 Panfrost BO 的 PRIME scanout，
   再接 VDIN NV12/NV21 的独立视频平面、跨设备 fence、背压及多消费者引用；
   不能把 RGB OSD 的零拷贝候选当成 HDMI-IN→OUT 直通已经完成。
