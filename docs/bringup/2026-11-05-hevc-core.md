## 资源与共享电源域

绑定允许旧 VDEC 资源和新增 HEVC 资源两种完整组合，设备树补充功能时钟、p0
父时钟和 HEVC 电源域。驱动先通过已验证的 VDEC 流程持有 DOS、NIC3 与 CPU
桥，再设置 HEVC 本地 gate、CCF 路径和 secure genpd；核对实际时钟寄存器后
才访问 HEVC。检查入口不加载固件、不启动处理器或 DMA，读取结果是缓存值。

独立核心的准备提交为 `3b5e7fcb8d5e5bc36772ed026cc9efe8721f48d5`。第二十三轮
因初始域已上电返回 EBUSY，未读取 HEVC 内部寄存器。第二十四轮允许 genpd
取得已有供电的引用，成功读取 MPSR 为零、parser version 为 `0x10001`，
CCF p0/p1 为 `0x100` / `0x80000000`，但要求物理关电的检查失败并保留模块。

代码与随后只读 genpd 记录确认：`fe09a000.temperature-sensor` 独立持有
`T7_DOS_HEVC`。这解释了初始上电和解码器释放后仍上电，不能当作固件残留，
也不能为通过检查而关闭温度监控。提交 `9b8a5bd515e92357b0c91f9c381cb348356e977b`
验证本驱动的 runtime PM 引用已释放，允许共享域继续供电；功能时钟引用仍按
顺序归还。后续解码的 DMA 安全必须由停机和 AXI 隔离证明，不能依赖域掉电。

实际 C 回归共 43 项通过，覆盖每个后端失败、错误时钟禁止内部访问、重复申请
释放和共享域消费者保留；模块编译与代码 strict checkpatch 通过。绑定 schema
和编译后测试板 DTB 校验通过。默认 PATH 缺少 dtschema，实际检查使用 VM 已有
独立环境，没有把工具缺失算作通过。新增测试目录已有 MAINTAINERS 覆盖；普通
任务提交没有作为带 Signed-off-by 的上游补丁发布。

## 双路时钟、停机与固件加载

第二十七轮新增有界停机检查。前端 AXI 返回 `0x8850`，后端一直为 `0x1010000`，
因此在固件加载前停止，保留资源并正常重启恢复。未执行 codec 回归；恢复接收
60.16 fps。离线对照确认 T7 的单核心不代表单时钟：芯片表的
`hevc_clk_combine_flag` 为 false，`pm_vdec_clock_on()` 同时开启 HEVCF 和 HEVCB。
此前仅有前端时钟，读 parser version 成功不能证明后端能够工作。

补齐 HEVCB、p0 父时钟、CCF 引用及双路实际寄存器校验后，第二十八轮使用完整
build 20，源码 `b1a45f0915d5eff335b1ddb2e7c3f4fa14c72d64`，Image build ID
`1b3917ce2224d2dccb46241df20706487f89773b`。两路时钟回读为 p0 `0x01000100`、
p1 `0`；前后 AXI 均为 `0x8850`，IMEM/LMEM DMA 与写响应等待通过。HEVC DMC
client 配置和 HEVC_MMU secure 固件加载返回成功，随后再次停机、归还引用通过；
没有启动 AMRISC，没有交付 HEVC 解码帧。

停机要求前后各自的读、写确认位均满足；5.15 的检查是任一位满足就继续。当前

## 格式接入边界

现有 HEVC 草案依赖私有参考帧控制，10-bit 输出降成 8-bit，不能直接宣称标准
接口与完整位深已实现。[标准 stateful 接口](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/dev-decoder.html)
要求输出显示顺序、动态尺寸事件和排空；固件已有完整码流解析能力，应结合它
评估接口，不能把逐帧 Annex-B 私有试验包装成完整 stateless 支持。
HEVC、VP9、AV1 共享该核心，codec、固件切换、DMA 停机和长期 KVM 共存仍待实现。
