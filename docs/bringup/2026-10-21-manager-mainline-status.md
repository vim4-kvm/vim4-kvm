# 2026-10-21：7.x 管理器状态、界面与 WPA3 适配

摘要：用户反馈的 PD「暂无记录」、CPU 功耗一直采样和内核界面风格问题已修复并部署，
实际浏览器核对通过。无线连接失败发生在 WPA3-only 网络：原接口没有提供 SAE AKM，
NetworkManager 使用 PSK 后以 ssid-not-found 超时。现已补齐 BCM43752 的外部 SAE 路径；
能力声明与真实联网验收分开记录，不以能力列表替代认证、DHCP 和传输结果。

## 状态与界面

- FUSB302B 的物理 AO-A 控制器相同，但 5.15 与 7.x 分别枚举成 I²C-6 和 I²C-1。
  `usb-pd-init` 按设备树物理路径定位，拒绝多个匹配或内核驱动已占用的控制器。
  `--status` 仍只读器件 ID 与 STATUS0，不读取清零中断或 FIFO，也不重新协商。
- 7.x 没有 Linux TCPM，沿用 U-Boot 初始化。此前运行时注释把“不运行用户态协商”
  误写成“由内核 Type-C 驱动负责”，已纠正。页面显示实际 VBUS 检测与额度不可读；
  没有把 USB 枚举、供电能力或电流额定值冒充协商结果。
- 当前 7.x 没有注册 Energy Model，但有实际 OPP 电压、设备树动态功耗系数和频率驻留计数。
  助手按内核 `dev_pm_opp_calc_power` 的 C×V²×f 模型补齐每频率估算，再复用区间加权与
  各核忙碌率。读取运行时经过速度分档调整的电压，不使用静态 DT 名义电压。
  同时接受有物理单位的毫瓦、微瓦 Energy Model；无效或抽象单位仍拒绝。
- `cpuPowerAvailable` 区分模型不可用与等待第二个有效区间；界面不再无限显示正在采样。
  实测空闲窗口连续约 0.17–0.18W，仅为 CPU 动态功耗估算，不是整板功耗。
- 内核面板复用现有应用卡片、默认启动标签、运行状态、按钮与行内确认样式。
  实际浏览器检查桌面和 390px 手机宽度、取消确认、无水平溢出及无页面异常；未提交重启。

## 无线协议与固件边界

固件仍为 `01-16e134aa`，SHA-256
`af7310c6c44da2690ea9f666eea8477a48e906810a1246a5fa207d3788fdf309`。
没有替换 NVRAM、修改地区或要求用户降低路由器的 WPA3 设置。

固件宣称 `sae/extsae`，但不提供驱动探测的 `sup_wpa`，也没有 Infineon 的 `sae_ext` 协议。
因此不能只把 extsae 当成同名能力别名。WCC 实现按板上厂商驱动的 Broadcom 协议处理：

1. JOIN_START 携带 SSID/BSSID，先暂停关联，再向 supplicant 请求外部认证。
2. 完整认证帧经 `assoc_mgr_cmd` 发送；AUTH 事件的帧体补齐 802.11 头后交给 supplicant。
3. 成功才恢复关联，失败或无法发起认证时终止；检查长度、SSID、接口类型和连接状态。
4. 显式公布 STA 的 SAE AKM。Ubuntu wpa_supplicant 2.10 不会从 fullmac 的 SAE 标志
   自动推断 CONNECT 路径的 AKM；热点与其他接口不宣称 STA 专用的 SAE 能力。

配置回调在固件能力发现之前安装，回调执行时再检查能力；wiphy 能力在发现固件能力后设置。
管理器对可见 WPA3-only 网络检查 SAE，支持时用 `key-mgmt=sae`、PMF required；
不支持时在任何连接变更之前报出具体原因。混合模式保留 PSK 兼容路径。

测试候选重启时复现了既有 P2P IF_ADD 超时和固件崩溃，保存器留下私有转储。
最终对 BCM43752、FWID `01-16e134aa` 屏蔽 P2P 能力，避免失败的 P2P-device 初始化；
STA 与 WPA2 AP 不依赖 P2P。这是针对已知失败路径的兼容处理，不能据此宣称历史固件
崩溃根因已全部解决。新固件需要重新验收后才能解除该限制。
