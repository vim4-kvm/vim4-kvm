## RNG 与 KASLR 依据

厂商 5.15 的 `common_drivers/arch/arm64/boot/dts/amlogic/mesont7.dtsi`
给出 `0xfe440788/0xc`、`version=2`；厂商 `common_drivers/drivers/char/hw_random/meson-rng.c`
在版本 2 路径对 `+0x00` 的 bit31 发握手，等 bit31 和 bit0 清零，再读 `+0x08`。
7.3 的 `drivers/char/hw_random/meson-rng.c` 中，这一路径对应
`amlogic,meson-s4-rng`；`amlogic,meson-rng` 只读 `+0x00`，不能照抄厂商 compatible。
新节点使用已有 S4 binding，不带旧 `version`、`quality` 属性，不新增寄存器操作。
`CONFIG_HW_RANDOM_MESON=y` 已在 UHD 配置中，未修改发布配置或已部署源码锁。

`arch/arm64/kernel/pi/kaslr_early.c` 早于平台 RNG probe，只取 `/chosen/kaslr-seed`
或 CPU RNDR。板上 Cortex-A73/A53 的 Features 不含 RNDR；增加 hwrng 节点不能
给本次启动的早期 KASLR 补种。若需启用 KASLR，启动固件仍须提供合适的新鲜种子；
本任务未修改 U-Boot，没有写入固定或伪造种子。

### 随机数采样的实际结果

两轮各执行两次 `dd if=/dev/hwrng bs=4096 count=16 iflag=fullblock`，
四份均完整得到 65536 字节、16384 个互异 u32、全部 256 种字节值，摘要各不相同。
没有读取失败、全零或恒定输出。
首轮 `rngtest -c 100` 为 100 成功/0 失败；重绑定后的第二轮为 99/1，
失败项是 Long run，返回码为 1，不能写成全部 rngtest 通过。
因此追加有界的独立 1000 块采样，结果为 999/1，同样只有 Long run 失败，
Monobit/Poker/Runs/Continuous run 均为 0。未将这些统计失败直接归因硬件故障或误报。

追加原始样本保留为 `/var/tmp/vim4-diag/rngtest-1000.bin`，2502500 字节，SHA256
`15a401cab353e0793f3c74785ef86dc56e08d82be375481c9c19e0dd9f777f8a`。
本轮证明 hwrng 注册、连续读取和 CRNG 提前初始化；随机源长期质量及上述统计失败的
