# 2026-11-05：RESET/VBUS/PD 闭环采样方案，未排板

**仅方案，未获新的板窗或物理接线授权。** [r60](2026-11-05-vdec-coldboot-ab-r60.md)
证明正式包的 RAM 和 eMMC 启动均可复位，进入
[区分方案第5步](2026-11-05-vdec-boot-diff.md)。现有 UART 不能区分供电下降、
外部 RESET 或固件触发 reset。保留正式包，不以逐个禁用驱动替代测量。

## 先准备、后共同批准一次窗口

先核对板卡版本的原理图/可访问测试点、信号电平和仪器输入范围，确认 RESET
的准确网络名与有效电平。用户需确认能否在场接线及具备示波器、合适探头和
可解码 USB PD 的分析仪；不要求用户盲接 GPIO，不推定已具备仪器。
连接方案、探点照片、共地/隔离方式与设备带宽由实物确认后写成清单再批准。
接线和插入 PD 分析仪可能改变阻抗/时序，记录拓扑并保持不动。

同时捕获板端供电入口 VBUS、RESET 网络与 CC 上的真实 PD 报文；若通道允许再采
关键电源轨，分清输入掉电和板内稳压/复位动作。示波器保留触发前后波形，PD
分析仪保留原始包与方向；触发用 VBUS 下降或 RESET 有效边沿，不只靠 UART 字符。
带宽、采样率、阈值和预触发长度待仪器与电平确认后定，不在未知硬件上假定数值。

宿主连续保存 UART 原始字节与时间戳，软件仅使用现有 TCPM/FUSB302 日志/trace；
先离线确认事件是否可用，禁止另用原始 I2C 读取会清状态的寄存器。
记录 Get_Source_Cap TX、超时、HARDSENT/收到 Hard_Reset、VBUS-low、RESET 和 BL1
的顺序。用可共同观测的同步事件对齐仪器与宿主时间，并保留对齐误差；不得把
USB UART 收包时间当作精确硬件边沿。

## 判别与停止

- PD Hard_Reset 在先、实际 VBUS 掉落随后，再到 RESET/ROM：支持供电链路假设，
  仍需区分发起方及协商状态，不能仅凭软件 Hard_Reset 字样归因。
- VBUS 保持而 RESET 有效：继续区分外部复位源、板内监控和固件动作。
- 可测 VBUS/RESET 均无对应边沿而回 ROM：保留仪器覆盖边界，调查其他电源轨、
  看门狗/SoC reset 原因，不宣称已排除所有供电问题。
- 首次完整异常证据或 BUG/WARN/挂死/恢复失败即收尾，不以连续主动 reboot 凑概率。
  次数和时间预算另由协调者批准；如果无法恢复 SSH，停止主动操作并由用户/协调者
  决定物理断电或回退，不自动改默认、不 saveenv。

每次必须锁定 release/build ID、启动路径、rootfs/供电源、实际模块参数和探针版本；
修好的采集器先离线验证再考虑使用，额外 Python/trace CPU 扰动要列明。
最终按正式 proof 核保护文件与视频，波形、PD 原始包、UART、软件日志分别归档。
本方案没有安排重启、物理测量或新板票。
