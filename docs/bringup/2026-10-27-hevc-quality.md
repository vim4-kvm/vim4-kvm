# 2026-10-27：HEVC 无损与固定 QP

5.15 One-KVM 的视频输出设置增加目标码率、固定 QP（0–51）与无损模式，
默认继续按码率控制。设置作用于共享 HEVC 编码，网页、UU、SRT 和录屏共用。
H.264 保持现有路径；7.3 Wave5 不开放新模式，使用保存的码率配置。
源码：gst-plugin-venc `3c9bd56533df575b92eead2f372648b912909f82`，
One-KVM `61160fc65f7a8ff303a2b88261ee7fa01b9bd085`。

## 实现

扩展私有 SDK 插件 `vim4hevc10enc` 接受 NV12/NV21/P010，按实际输入输出 Main/Main10。
八位系统 libamvenc ABI 不变，普通 SDR 码率模式仍使用旧插件。
固定 QP 使用 SDK 的 `forcePicQpEnable` 和 I/P/B picture QP，并关闭码率控制；
无损使用独立的 lossless 开关，SDK 同时关闭 RC、降噪、ROI 与帧内刷新。
没有把 QP=0 当作无损声明。

应用将偏好保存在输出配置，修改尺寸或 UU 临时 HDR 请求不会抹掉偏好。
默认模式不序列化新增字段，以兼容旧版严格解析器；回退旧应用前先恢复目标码率。
编码包提供 `vim4-hevc-quality-api-1`，应用包声明依赖，避免只更新应用后缺少插件属性。

## 硬件验证

板子内核 `5.15.137-vim4kvm-hdrdual6`。以 khadas 运行，独占编码器并停止 One-KVM，
结束恢复服务。`gst-plugin-venc/tests/hevc-quality.py --exclusive` 使用 640×384 固定种子
噪声输入，每种模式五帧，分别验证 NV12、NV21 和 P010/PQ。

- 三种格式的无损输出经 ffmpeg 解码，每个输出字节均等于输入，差异为 0。
- QP 18、40 的实际 PPS 初始 QP 加 slice QP delta 均与设置一致，覆盖 I/P 帧。
- 检查实际 Main/Main10 profile 与 PQ transfer，固定 QP 输出大小随 QP 增大而下降。
- P010 无损样本输出 667844 字节，NV12/NV21 约 465198 字节；这是此测试内容的大小，
  不能据此推算真实桌面或视频的码率。

最终已部署插件再跑同一套像素与 QP 检查也通过。证据：
`build/hevc-quality/hardware-deployed.log`；插件离线 DMA 退休、CPU 回退和
七项源管线测试在 `build/broadcast/quality-build-final.log`。

## 网页与恢复

Chrome 156.0.8078.73，无界面运行，真实 Mac mini HDMI 桌面输入 3840×2160/60 SDR；
每轮预热 2 秒、采样 8 秒，无并行编译。下列各轮没有新增 freeze、解码丢帧或丢包：

| 模式 | 接收尺寸 | 解码 fps |
|---|---|---|
| 固定 QP 28 | 3840×2160 | 60.08 |
| 无损 | 3840×2160 | 59.98 |
| 固定 QP 18，GE2D 缩放 | 1920×1080 | 60.07 |
| 无损，GE2D 缩放 | 1920×1080 | 59.95 |
| 保留无损偏好，切 H.264 | 1920×1080 | 59.95 |
| 恢复目标码率 | 3840×2160 | 60.08 |

这些是当前桌面的短测，不代表复杂运动、高噪声输入或光学端到端延迟。
无损轮次接收数据量明显高于固定 QP，不能把原来的 40000kbps 设置当作实际带宽上限。
网页选择固定 QP 18 后保存，API 返回一致设置；非法 QP 52 返回 400 且不改配置。
只改尺寸时保留无损偏好；服务重启后固定 QP 设置保留。最终恢复普通码率和原输出限制，
运行模式恢复 H.265。证据为 `build/hevc-quality/browser-test.log`、各模式日志、
`ui-test.log`、`video-before.json` 与 `video-after.json`。

VIM4 Rust 测试 799 通过、4 忽略；前端构建及 9 项测试通过。

## 边界

无损保留编码器输入的 YUV 样本，上游 HDMI 颜色转换、4:2:0 和缩放的损失仍存在。
新模式不受目标码率约束，不承诺所有内容的 4K60；复杂运动/噪声内容需要单独测带宽、
大帧恢复和帧率。UU 官方客户端、真实 HDR 屏光度、7.3 新模式均未验收。
