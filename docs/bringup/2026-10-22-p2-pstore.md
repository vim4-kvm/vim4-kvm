基于 `e0346697f25035c7eaa77fa44641a54d6e31e327`，提交

依据厂商 5.15 `80a07ad5406d57855c996285ae75a50a1b9147ae`，common_drivers
`4cfb128d36f8511b2db1bd13c08d5704347ded49` 的
`arch/arm64/boot/dts/amlogic/kvim4n.dts:74`：

```dts
ramoops@0x07400000 {
    compatible = "ramoops";
    reg = <0x0 0x07400000 0x0 0x00100000>;
    record-size = <0x20000>;
    console-size = <0x40000>;
    ftrace-size = <0x80000>;
    pmsg-size = <0x20000>;
};
```

候选沿用物理地址/总量、128 KiB record 和 256 KiB console；不启用 ftrace/pmsg，
剩余空间供 dmesg records。保留默认 mem-type=0，不增加无依据的 no-map、ECC 或地址猜测。
正常重启测试目标为 `console-ramoops-*`；默认 max-reason=2 不要求普通重启产生
`dmesg-ramoops-*`，也不通过修改 panic 策略制造记录。

| 区域 | 地址范围 / 依据 |
|---|---|
| BL31 / BL32 | 7.3 DTS `0x05000000–0x052fffff` / `0x05300000–0x072fffff` |
| ramoops | 厂商已预留的 `0x07400000–0x074fffff`，与安全固件区分离 |
| CMA | 启动参数 `512M@0x10000000-0xf0000000`，低端界在 ramoops 之上 |
| PCIe restricted DMA pool | 动态分配，memblock 先排除静态 reserved-memory |
| U-Boot 加载 | FDT `0x01000000`、Image `0x01080000`、overlay `0x00a00000`；FullKvm 无 initrd |
| 其他缓冲 | ramdisk `0x10000000`、解压区 `0x0d080000`/32 MiB，均不覆盖本区 |
| U-Boot 映射/高端 | kvim4.c 常规映射 `0..0x050fffff` 与 `0x09000000` 起；usable RAM top 上限 `0xe0000000` |

保留区不与上述已知用途冲突。BL2 DDR 初始化等二进制固件内部清零行为不能靠 DTS 证明，
实际跨正常重启读回才验证当前启动链；不能外推掉电、冷启动、所有 reset 路径。
来源摘录 `logs/p2-round2/pstore-vendor-layout.txt`。
