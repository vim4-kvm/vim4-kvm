# 2026-11-06：MPEG-2 P 链漂移的逐步算术定位

att/teracom 的长 P 链误差已定位到**每步残差的单位舍入差沿参考链累积**。
teracom 有直接数值证据：固定零运动块的反量化系数在 64 张 P 图像中不变，
同一像素硬件每帧减 1，ISO 每帧减 2，最终差 64；其首错块没有半像素插值、
系数饱和或像素裁剪。att 的零运动块同样存在 ±1 残差差异。

其余 15 条最大差 3–6 的共同点是：以硬件参考帧逐步重解码后，新解码图像与
硬件全部不超过 2。不是以这个实验替换原验收；原始全参考链的 Fail 保持不变。
这排除了“当前图像突然产生 3–64 级错误”的解释，但不证明每条流的每个不同像素
都来自同一硬件精度位。尚无可证明正确的寄存器/微码修改，本轮不提交内核修复。

接续 [r69 首错及单向 B 调查](2026-11-06-mpeg2-r69-analysis.md)。sony-ct1/ct2
的零帧问题已有独立 topic，不混入本轮 17 条漂移分析。

## 方法、校验和边界

继续只读主工作区 r69 归档，本工作树 `build/mpeg2-rounding/` 留原始输出、
一次性脚本和私有实验源码；VM 的 `/home/deepdream/build/vdec-mpeg2/rounding-*`
保存参考源码副本、二进制、样本和图像。没有改原 ISO 解码器或 r69 证据。
原 ISO 二进制 SHA 与 r69 tools-manifest 的 `bin/mpeg2decode` 相同：
`a7378621dcea43939087c846d1d7f486085429fef6c53526469e8d2ec582e776`。
实验二进制及源码摘要见 `experiment.sha256`；带许可的原源码/改本均只保留本地，未入库。

使用 ISO 解码器已有的 `-x/-g` 帧缓冲截取：在解码当前图像前，按其原逻辑将
参考图像换成指定 I420 文件中的对应帧。先喂 r69 的 ISO 参考，再喂硬件输出。
为避免参考帧替换覆盖延迟输出，在 `picture_data()` 后保存刚解码的图像副本，
按真正 `Write_Frame()` 的显示序号输出副本；两场分别保存，第二场替换同帧参考
时不丢失先前保存的第一场。用实际输出映射校验解码/显示序号，不仅依赖 ffprobe 编号。

17 条 Fail 加 4 条对照，共 21 条，用 ISO 自身参考截取、reference IDCT 重解码，
**每条都与 r69 ISO YUV 逐字节一致**；尺寸、帧数和所有帧长度也一致。
这验证截取、场对合成、显示重排与图像保存方法。之后换成硬件参考帧，才比较当前
新解码结果与硬件；仍使用原 `abs(diff)>2`，不寻找偏移、不放宽容差。

初次 `intercept.py` 直接比较 ISO 常规输出，其中延迟 anchor 已被替换，数据不能用作
新图像误差证据。有效实验均由 `captured.py` 和新增保存点产生。
一次 teracom 单块追踪的路径写错，ISO 只打印替换失败却返回 0；失败日志保留为
`teracom-all-invalid-path.log`，修正为实际 decode-0010 后重跑。有效日志全部检查
无替换失败，后续脚本同时检查进程状态与日志，不把返回 0 当作截取成功。

## teracom：可逐项核算的舍入累积

首错显示帧 3，Y(455,80)，对应 MB253 的第一个 8×8 块。P1–P64 的该块均为：
零运动、frame prediction、frame DCT，qscale=8、q_scale_type=0、alternate_scan=0。
反量化 DC=-12，其余 AC 原先全零，mismatch control 后最后系数为 1。
reference IDCT 产生 -1/-2 棋盘残差；对相同硬件参考，硬件在块内 (7,0) 产生 -1，
ISO 产生 -2，该块其余 63 个位置一致。预测值在有效范围内，差异不是裁剪造成。

| 显示帧 | 硬件 Y(455,80) | ISO Y(455,80) | 差 |
|---|---:|---:|---:|
| 0 | 255 | 255 | 0 |
| 1 | 254 | 253 | 1 |
| 2 | 253 | 251 | 2 |
| 3 | 252 | 249 | 3 |
| 64 | 191 | 127 | 64 |

`teracom-all.log` 验证了 64 次相同系数和零运动；`teracom-proof.json` 保存完整轨迹、
硬件残差与系数候选比较。去掉 mismatch 系数会把空间棋盘变成常数，改变大半像素，
无法解释只差一个位置；把 DC 改为 -11/-13 也明显更差。结合无插值、无饱和及精确
整数反量化，该处已收敛到 IDCT 残差舍入差异。仍未确定硅实现的具体常数/中间精度，
不能从这里推导一个应修改的内核位。

## 候选逐项核对

| 候选 | 实际实验 | 结果/边界 |
|---|---|---|
| IDCT 舍入 | att 全部 3168 个零运动块，201044 个未裁剪像素；用硬件预测值从输出反推残差，与浮点 IDCT 对照 | 3424 个像素差 ±1、无更大差；首错 MB 也有正负单位差，已与 MC 分离 |
| 固定点 IDCT 具体算法 | 分别改变变换常数精度、行/列顺序、中间精度和首次舍入，先取样再对前 12 个候选全样本复核 | 没有得到与硬件逐字节一致的模型；不能把最佳拟合当作硬件算法或修复 |
| 系数/像素饱和 | 21 条采集块的反量化系数范围；att 未裁剪像素单独比较；teracom 固定块逐值核算 | 全部采集首块均无需系数饱和；teracom 残差和目标像素也不触发裁剪，不能解释其首错 |
| 半像素插值舍入 | 对 8 条代表（含 att/teracom 零运动控制）分别测试标准公式、先横后纵/先纵后横两次平均、以及四点和加 3/0/1 再除 4 | 标准公式误差最小；替代公式普遍更差，att/teracom 完全不受这些开关影响。无证据改插值逻辑 |
| 反量化系数统一偏移 | att P 块系数在标准结果上按符号加减 0.5 或 1，再做 IDCT | 原系数仅 3390 个残差差异，偏移后变为约 3万–5.5万；不支持统一改变反量化舍入，但没有据此测试所有可能的反量化实现 |
| intra DC precision | 首错 picture/控制为 0/1/2 均有，首错采集点都是 inter 块；MPEG-2 inter DC 不走 intra 专用 DC predictor/precision | 不能解释零运动 inter 的 teracom 首错；未发现驱动序列化 precision 位错误 |
| q_scale_type 非线性表 | 两种类型均有，参考解析得到的 qscale 与原位流和软件反量化路径一致；teracom 类型 0、qscale8 的 DC 反量化为精确整数 | 未见一类标志或非线性表转换错误；没有由离线像素证明固件内部表每项均正确 |
| alternate_scan | 两种扫描均覆盖；原控制/重建头位一致；teracom 首错关闭 alternate scan，且仅 DC 与 mismatch 系数 | 不是长 P 链共同根因；没有证据更改驱动扫描位 |

例如双向 conf2 的标准插值新图像仅 359079 个像素不同；两次平均变为约 122.6 万，
改变四点和偏置也更差。tcela-9 同样从标准的 742847 处增至约 166.8万–271.8万。
这类反事实只用于排查，没有替换标准参考或改真实驱动。
