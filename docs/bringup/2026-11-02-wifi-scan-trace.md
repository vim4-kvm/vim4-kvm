# 2026-11-02：BCM43752 连接崩溃定位到扫描窗口

默认 FullKvm 7.3，保存的 5 GHz 网络。独占板窗内通过 tracefs 实例给六个
brcmf_fil_{cmd,iovar,bsscfg}_data_{get,set} 入口及返回点加 kprobe。
记录命令号或 iovar 名和返回码，不记录数据内容。原始轨迹、转储归档和
实验模块差异保存在本地 `logs/wifi-trace/`。

默认模块第一组连续八次成功。第二组增加激活前读取 power_save，将两次激活间
radio off 后等待从 1 秒改为 0.4 秒；前五次成功，第六次崩溃。两组各自记录
2792/2792、1820/1820 条事件。十三次成功都是两次 escan 后一次 join。

新转储 wifi-1793599763154017231-devcd2，TRAP 4，PC 0x6e344，
AXI 地址 0x180013fe，对应 D11 的 phyregdata。此前同类转储的
0x180013fc 对应相邻的 phyregaddr。可定位到固件接受扫描后、请求关联前；
目前无法分辨具体信道、PHY 操作以及并发的固件任务。

## 扫描 MPC 候选

内核试验分支 `wifi-43752-scan-mpc-trial`，提交 `e96f49fb7af9a`，
在 0d0bdced8193 上给 BCM43752 启用已有的 NEED_MPC quirk。驱动在 escan
开始前设置 mpc=0，在扫描结束或启动失败后设置 mpc=1。沿用正式构建产物和
符号表构建 brcmfmac.ko，仅在运行时加载。候选模块 build ID 为
a9411c411dd260dd1fda72368aade965e4ea8a53。

随后三组都从重新加载模块开始，使用第二组相同的激活流程。按实际执行顺序，
候选 8/8 成功、正式模块 12/12 成功、候选 20/20 成功。候选两组共观察到
112 次 brcmf_set_mpc 的 iovar 设置，全部返回 0。各组探针缓冲区无覆盖。
正式模块本轮总计 1/26 崩溃，候选 0/28。正式模块也有长成功序列，且各组非
随机交错；尚不足以确认降低了故障率。下一次应匹配固件运行时长、交替多组，
并记录第二次扫描的频道列表和出错前最后一个可观测的频道事件。
