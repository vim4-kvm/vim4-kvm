**冷复位不是解码系列独有：正式 fd41fb5 的 RAM 对照和 eMMC 默认启动都复位，
同一实验及恢复链内连续发生。** 仅完成三个实验启动，随后按恢复失败停止，17 项
未运行、不补样。最终正式默认、2372 项保护文件和真实视频核验通过，未部署候选。

## 实验分母

和两组包；替代票 order 1320 / `441b81e40c3c4638a20cd8d41e61aaf1`，上限50分钟，
全程 sampling。显式选择 `/dev/cu.usbserial-1100`，先读到 Ubuntu/Khadas ttyS0
login，入场 proof、同分区 st_dev 门禁和视频通过。没有在窗口内改工具或封包。

| 实验 | 60 秒观察结果 | 冷复位距 Linux 起点 |
|---|---|---|
| A1，正式包 RAM | 完成，无复位 | — |
| B1，既有 .28 RAM | 完成，无复位 | — |
| A2，正式包 RAM | 冷复位；其后自动恢复再复位而停止 | 8.059399542 秒 |

A：2 次启动、1 次复位、8 项未运行；B：1 次启动、0 次复位、9 项未运行。

A2 末条带内核时间戳的 UART 日志是 `[5.204806] brcmfmac` 固件身份行
（18.35.387.23.217）；末条日志不是复位瞬间，也不能据此归因 Wi-Fi。

## 恢复启动另列，不加入 A/B 分母

| 顺序 | 正式 eMMC 启动 | 距 Linux 起点 / 末条内核日志 |
|---|---|---|
| 自动1 | A2 后自然恢复，又复位 | 9.092736833 秒；`[6.183694] brcmfmac` 同版固件身份行 |
| 自动2 | 上述复位后自然恢复成功，SSH/proof 通过 | Linux 起点 monotonic 659976692104791；无复位间隔；原连续 UART 收到的末条内核行 `[2.957455] systemd[1]: Listening on systemd-journald-dev-log.socket`，后续 SSH 成功另有证据 |
| 请求正常 reboot | 清理后唯一一次主动正式 reboot，又复位 | 7.505441792 秒；`[4.518506] brcmfmac` 同版固件身份行 |
| 最终被动自然恢复 | 不再发 reboot，SSH/proof/视频通过 | Linux 起点和末条内核日志处于 UART 交接空档，未覆盖；不能补填时长 |

四个恢复启动不是三次：自动2的 Linux banner 明确存在于原 r60 UART，不漏计。
最后一个自然恢复由已观察到的 ROM 与后续正式身份核验确认；交接空档内是否还有
额外超早启动未知，因此跨窗口总数采用下界。时间均按完成对应 UART 行的宿主
monotonic 收包块计算；不是硬件 reset 边沿，首字节所在块可能更早。

原窗口因自动1恢复失败退出，SSH 当时不可达，收尾未完成。随后获批仅恢复票：
先被动等 SSH 并核全量 proof，按 hash 删除 owned-firmware.json 里的唯一 B 固件副本。
首次清理因 `/tmp` helper 已被启动清理而安全停止在 reboot 前；补传仓库 helper 后
清理候选和 B 空 module mountpoint，A 正式模块目录没有 marker，跳过不动。
请求正常 reboot 再复位后，仅被动等待；最终自然恢复成功，没有主动 reboot 循环。

最终 release `7.3.1-vim4-20261105` / build ID
`bdbfa439f298e92b5bad092528d11119a974f262`，2372 项保护文件相等。
实际视频 3840×2160、59.3693 fps，帧推进，dropped/freeze/lost 无新增。
两个私有候选目录及唯一 owned 固件副本均确认不存在，所有票已释放。

## 采证缺口与离线复现

早期、ready、end 三个时点的**模块参数和 lsmod 均未覆盖**。两组 Python 探针都启动，
但创建快照子进程时立即异常退出；扰动对两组相同，却不是计划中持续采集的扰动。
Python 本身占用早期 CPU，可能影响时序，不能与未插桩生产启动视为等价。
ready/end tar 传输和 hash 成功，只能证明归档传输正确，不能证明内含参数快照；
其中保存的 dmesg/journal/services 仍有效。没有用恢复启动补原启动的缺失参数。

事后在 VM 离线复现：`/usr/bin/python3` 以空环境、argv[0]=`python3` 启动时，
`sys.executable` 为空，原子进程调用得到同样的 `PermissionError: ... ''`；
改为绝对 argv[0] 或提供 PATH 后正常。此机制已复现，板端环境全集未捕获。
修复另作提交，当前窗口和包不追改、不补跑。
