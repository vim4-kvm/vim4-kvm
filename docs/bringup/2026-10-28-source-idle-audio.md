# 2026-10-28：源端空闲时非静音音频与数字静音恢复

用户更换 HDMI 源为另一台 Mac mini，反馈源端没有播放声音但仍持续有声。
实际共享音频流含显著非零数据；应用内重开采集无效，源端向 HDMI 输出三秒数字静音后，
解码样本归零，停止静音播放后仍保持为零。现象符合 HDMI 链路残留旧样本，
尚不能细分为 macOS 发送端、HDMI RX 或板端音频硬件；不据此修改 UU 协议或增加音量门限。

## 环境与方法

- 板子内核 `5.15.137-vim4kvm-hdrdual6`，安装包 `vim4-onekvm 2.5.1+vim4.20261025.20`。
  前一轮本地 UU 连接稳定性修复未部署，与本次现场版本分开记录。
- 源端 macOS 27.0.1（26A434），默认输出 RTK UHD HDR，48 kHz 双声道 HDMI。
  CoreAudio 进程属性查询当时未报告运行中的音频 IO；未据此宣称所有应用绝无音频数据。
- One-KVM 使用 `hw:AMLAUGESOUND,0`，音频 high，TDMIN_B 来源 hdmirx。
  通过现有 `/api/ws/audio` 订阅共享 Opus，不另开 ALSA 设备，不占用编码器或 HID。
  libopus 内存解码为 48 kHz 双声道 S16，计算峰值、RMS、非零样本数与包长，不保存录音。
- 查询期间 UU 云端 online、桌面会话数为零；不能宣称真实 UU 客户端听感验收通过。

## 对照结果

| 阶段 | 五秒窗口结果 |
|---|---|
| 初始 | 251 包，481920 个双声道样本，峰值 13986，RMS 3307.25（−19.92 dBFS） |
| 再次订阅 | RMS 3295.23（−19.95 dBFS），非静音持续 |
| 仅重开应用音频采集 | RMS 3319.94（−19.89 dBFS），未恢复静音 |
| Mac HDMI 输出三秒数字静音 | 首秒后峰值降至 2，随后样本全零 |
| 静音播放结束后再订阅 | 251 包，每包 3 字节，481920 个样本全部为零，峰值/RMS 为零 |

应用音频 stop/start 期间取得本机和板子 `/tmp/vim4-board.lock`、`/tmp/vim4-heavy.lock`，
结束恢复 streaming/enabled，不修改持久配置。源端只用 afplay 播放临时全零 WAV，随后删除；
不播放测试音、不改变输出设备或音量。One-KVM PID 1533、HDMI 服务 PID 1097 与启动时间不变，
不重启服务、不改 EDID/HPD、不操作显示或键鼠。采集重开不能区分板端硬件与源端残留，
不能把其无效结果当作排除全部板端路径。

## 结论与边界

此次真实非静音输入已经消失；只是持续发送音轨与 Opus 静音包仍属现有行为，
不能仅根据客户端播放指示或 RTP 包持续到达判断仍有声音。
数字静音对照证明源端新样本能改变被观测链路，未证明具体哪个硬件缓冲残留，
也未完成非静音→停止的可控重现、物理 HDMI 拔插或长期验收。
若再次出现，优先取得源端停止前后与板端的样本能量对照，不用停止 UU 发送来掩盖非零输入。

本机临时测量器与最终零样本统计在 `logs/uu-source-audio-20261028/`（不入库）；
仅保留脚本和聚合统计，无 PCM、Opus 载荷或登录凭据。本轮没有生产代码修改。
