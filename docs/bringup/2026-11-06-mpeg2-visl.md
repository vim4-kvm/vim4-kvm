## 三类结果与修正

| 分类 | 流 | 证据与边界 |
|---|---|---|
| 用户态控制错误，6 条 | att、sony-ct4、sony-ct1、sony-ct2、Tek-5-long_conf4、ibm-bw | 两 parser 相同错误；修正后头字段/矩阵零差异，硬件像素尚未复验 |
| 控制正确且驱动根因已证明 | 无 | 未取得足以提交内核修复的因果证据 |
| 待证，13 条 | CSV 中 pending-pixels | 已核字段正确、请求完整；引用/缓冲和硬件像素根因未证 |
| 另列输入格式边界，6 条 | MEI、MEI.stream16、tcela-16、tcela-18、tcela-19、ccm1 | 原套件名称包含 MPEG2，但无 sequence extension，FFmpeg 识别 MPEG-1；两 parser 均输出 mpegversion=1，0 请求、not-negotiated。不是 parser 漏图像，也不是 MPEG-2 微码像素失败 |

若必须用三个桶表示：用户态错误 6、已证驱动错误 0、待证/格式边界 19；
六条 MPEG-1 不应偷偷改成 MPEG-2 Success，原 43 条分母也不修改。

第一处：picture quant_matrix_extension 的 load_intra/non_intra 同时更新相应色度矩阵，
之后显式 chroma load 才覆盖。原插件仅更新亮度，att 首图像亮度全 8、色度仍默认。
[FFmpeg 的 load_matrix/quant_matrix_extension 实现](https://github.com/FFmpeg/FFmpeg/blob/master/libavcodec/mpeg12dec.c)
也执行此继承。补丁在私有源码锁中加载；真实 C 回归覆盖 att 更新、显式色度覆盖及后续无更新保留。

第二处：codecs 基类检测到 sequence header 与前一次字节相同时提前返回，未通知
new_sequence；picture 改过矩阵后，即使遇到相同 sequence 也应恢复序列矩阵。
sony-ct1/ct2 的亮度差异由此产生。补丁只置 seq_changed，沿现有 new_sequence 通知，
不要求 drain。固定组两条的亮度及色度差异均消失。
