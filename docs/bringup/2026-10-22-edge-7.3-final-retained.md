## 检查器与执行入口

EDID 恢复后最多等待 35 秒，记录首次未锁定和随后恢复状态；超时先保存 dmesg、
HDMI RX、VDIN、服务日志，以及 Mac 的 mac-hdr-mode/system_profiler 源端模式，再回退。
因此能区别即时检查过早与等待到期仍未恢复，而不把瞬时 link_ready=0 当作故障。
原始模式选择 5、7、18，即 720p50、1366×768、4K60；默认仍检查全部 19 模式。

```sh
python3 packaging/kernel-edge/final-regression.py prepare \
  --destination build/deploy-7.3-final/regression-v3 \
  --logs logs/kernel-edge/deploy-7.3-final-round3 \
  --sample-modes 5,7,18 --wifi-scan
# 按第二轮相同提交与产物执行 stage，输出 bundle-v3；dry-run 校验完整清单。
python3 -u packaging/kernel-edge/final-window.py window \
  --bundle build/deploy-7.3-final/bundle-v3 \
  --backup /var/backups/vim4-deploy-7_3-final-round3-20261022 \
  --logs logs/kernel-edge/deploy-7.3-final-round3 \
  --archive-remote-to /var/tmp/vim4-deploy-7.3-final-round2 --execute \
  > logs/kernel-edge/deploy-7.3-final-round3-window.log 2>&1
```

入口自动嵌套 `/usr/bin/lockf /tmp/vim4-board.lock /usr/bin/lockf /tmp/vim4-heavy.lock`，
覆盖暂存、备份、安装、重启、回归及必要回退；locks.txt 保存实际两个 lockf 进程。
旧板端暂存目录在锁内移到 round2，不覆盖上一轮证据。
stage/dry-run 输出 `STAGED`、`OFFLINE_BUNDLE_VERIFIED` 与 `DRY_RUN: no SSH...`。

启动 `NEW_WARNINGS []`；扫描后最终新增一条：

```text
meson-gx-mmc fe088000.mmc: unaligned sg len 112 blksize 256, disabling descriptor DMA for transfer
```

SG 长度不能描述非整块大小，故本次传输不使用 descriptor chain DMA；这是 warn_once。
本次扫描成功、无固件崩溃或关键网络失败，但零新增 err/warn 检查记为未通过，
未在本轮更改驱动或证明该警告无性能影响。KASLR 无 seed、SCMI malformed reply、
PCIe IRQ、OP-TEE、brcm 固件信息等既有基线条目仍在；诊断修复的 crg 回调及旧风扇警告不再出现。
