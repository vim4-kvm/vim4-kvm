# 2026-11-02：BCM43752 下载余差与 SDIO 接收对齐

在[接收 CPU 修复](2026-11-02-wifi-rx-cpu.md)部署后，历史两次不同启动的
600 秒单 TCP 基准为 7.3 的 391.4 和 5.15 的 418.9 Mbit/s。按发送端每秒
吞吐统计，7.3 的第 10、50、90 百分位为 375.1、393.6、409.1 Mbit/s，
5.15 为 402.2、428.9、474.7 Mbit/s。两版的中位数也有差距。

## 同期切换内核

同一块板和 Mac，同一保存的 5 GHz 网络，iperf3 反向传输，板端绑定
wlan0 的设备与地址，SSH 走 eth0。依次测 7.3、5.15、重启回 7.3。
每次连接先预热 12 秒，依次做以下五段各 40 秒的测试。表内为接收端 Mbit/s，
UDP 括号内为接收端报告的丢包率。

| 负载 | 7.3 第一次 | 5.15 | 7.3 第二次 |
|---|---:|---:|---:|
| 单 TCP | 375.6 | 378.6 | 392.4 |
| UDP 目标 410 Mbit/s | 405.7（1.02%） | 379.2（7.52%） | 409.7（0.03%） |
| UDP 目标 455 Mbit/s | 415.8（8.54%） | 432.6（4.92%） | 426.1（6.28%） |
| 四条 TCP 合计 | 384.0 | 473.8 | 384.8 |
| 单 TCP | 390.9 | 398.3 | 385.9 |

单流区间重叠，本次没有稳定复现历史的 27.4 Mbit/s 全额差距。
四流差距明显，对应发送端重传分别为 7461、1296、7238。这里只在
5.15 的一次启动上测了四流，不能把重传数单独用作因果证据。

## DMA 中转复制

7.3 brcmfmac 的 brcmf_sdio_bus_preinit 设置固件的 bus:txglomalign，
它控制固件发送到主机的聚合子帧对齐，实机读回 8 字节。
本板 SDIO 功能 2 使用 256 字节块。meson_mmc_get_transfer_mode 检查
scatterlist 中每段的长度；不满足块对齐时，控制器改用中转缓冲区。
读完成后 meson_mmc_irq_thread 调用 sg_copy_from_buffer 分发数据。

在稳定流量中用 kprobe/kretprobe 配对统计该 MMC 中断线程的复制。
两次 7.3 启动各采 0.4 秒，分别得到 350、405 次复制，19.35、22.17 MB，
函数入口至返回累计 48.3、56.5 毫秒。此时间包含探针和调度开销，不能按
比例折算吞吐损失。5.15 的驱动不同，未观察到同名线程调用不能证明全程零拷贝。

随后始终保持 7.3、RPS 04、同一次连接。通过既有固件命令临时设置
bus:txglomalign，每轮开始前读回实际值，结束恢复。四轮单 TCP 各 60 秒：

| 对齐（字节） | 下载（Mbit/s） | 0.4 秒采样的中转复制次数 | 复制耗时（毫秒） |
|---:|---:|---:|---:|
| 8 | 378.1 | 387 | 54.2 |
| 256 | 390.6 | 0 | 0 |
| 256 | 393.1 | 0 | 0 |
| 8 | 386.6 | 386 | 53.5 |

每个聚合仍平均包含 35.3 至 35.5 包，四轮均无 rxglomfail 增量。
对齐对中转复制的作用可以逆转。吞吐收益另用反向顺序和更长传输测量。
实验脚本、逐秒速率、端点数据及原始探针记录在 logs/wifi-rx-residual-psLtTT/。

## 长样本与四流复核

将顺序反过来，单 TCP 各跑 300 秒：256 字节得 384.3 Mbit/s，8 字节得
387.5 Mbit/s。不同对齐下的中转复制变化仍与首轮一致。首轮短测的单流
吞吐收益没有复现。两种对齐都会改变总线上的传输布局，这个实验不能单独
测出纯复制成本对端到端吞吐的影响。

保持 RPS 04，四 TCP 以 8、256、256、8 字节各测 60 秒，依次得到
382.8、392.0、393.6、385.6 Mbit/s。另在同一连接上将对齐和 RPS 做
交叉对照，每格两轮 40 秒，次序前后对称：

| 对齐 | RPS | 两轮四流合计（Mbit/s） |
|---:|---|---|
| 8 | 04 | 376.2、347.6 |
| 8 | 0e | 379.4、385.2 |
| 256 | 04 | 389.0、391.6 |
| 256 | 0e | 343.8、387.6 |

负载中取 0.5 秒样本，统计 mmc2 的功能 2 CMD53 读请求字节数，并与
同期 wlan0 RX 字节增量比较。8 字节对齐的比值为 1.026 至 1.030；
256 字节为 1.030 至 1.054。比值含总线协议开销与采样边界偏差。
扩大 CPU 掩码或消除中转复制，都未在这些对照中重现 5.15 的四流峰值。

## 四流重传与接收队列

用四条 TCP 各跑 45 秒，在 5.15 同一连接切换驱动的 tcpack_suppress
并逐轮读回。按开、关、关、开的顺序得到 369.0、393.5、402.3、459.5 Mbit/s。
7.3 前后夹测为 378.7、385.3 Mbit/s；板端 TCPOFOQueue 分别增加 42171、
35284，发送端重传分别为 5750、3984。两版 TCPRcvQDrop、TCPBacklogDrop、
TCPOFODrop、RcvPruned 和 OfoPruned 在这组窗口都无增量。乱序入队计数
是系统范围计数，无法区分丢包后产生的序号缺口与真正的空口乱序。

另一次启动 5.15 后先预热 45 秒。再按关、开、开、关、关、开各测 45 秒，
下载为 370.5、287.6、297.2、293.6、305.3、307.2 Mbit/s。三轮开时
重传 2005 至 2661，三轮关时 5430 至 6682。ACK 合并确实减少重传，
吞吐却没有随开关重复升降。发送端 Mac 的路由经有线 en0。未同时记录 AP
发往板子的 MAC 重试、速率分布、Block ACK 与信道占用，尚不能定位序号
缺口产生在哪一跳，也不能把单流的历史差距全部归因于空口。

本轮仅提交取证记录。三组对齐实验均读回原值 8。最终为 FullKvm 7.3，
RPS 04，Wi-Fi disabled，默认路由 eth0，四项服务 active，UDC configured。
