# 2026-10-19：7.3 CRG UDC 与最小 HID 实测

结论：7.3 上 CRG UDC 已成功探测，Mac 能识别最小 HID 鼠标，连续报告提交和
20 轮重绑定通过，包括保持旧 HID fd/epoll 跨重绑定。修复了断开后仍显示 configured
的问题。尚未验证真实键鼠操作、复合 gadget、UAC2、虚拟磁盘或完整 KVM。

## 过程与结果

1. 新内核启动、SSH 和有线网络可用。PHY 使用 fe03a020 控制端口，与旧驱动的 phy-id=1 对应。
   手动加载 crg_udc 后出现 `/sys/class/udc/fdd00000.usb`。
2. 无 gadget 绑定时，三轮卸载、重新加载和 UDC 节点消失/重现检查通过。
3. 最小 relative mouse gadget 在 Mac IOUSB 树中出现，产品名 `VIM4 CRG Test`，
   序列号 `VIM4-CRG-TEST`；IOHIDDevice/事件服务也识别了鼠标按钮、X/Y 和滚轮描述符。
4. 初版测试脚本用零字节写解绑，configfs 不会调用 store，第二次绑定报 EBUSY。
   修正为写换行后，进一步发现驱动解绑未清除 gadget 的 configured 状态，
   测试误判新一轮枚举完成，HID 写入返回 ESHUTDOWN。
5. 修复 pullup 关闭成功后调用 usb_gadget_set_state(NOTATTACHED)，增加实际函数回归测试。
   替换模块后，三轮绑定/枚举/报告/解绑通过；另一次连续 10 个中性报告提交通过。
6. 正式运行工具 `--cycles 20 --keep-fd`：每轮完成枚举、连续提交 10 个中性报告、解绑。
   前一轮的 fd 和 epoll 注册保留到下一轮枚举及报告提交成功后才关闭，20 轮全通过。
   报告不移动鼠标、不按键；重复写入确认前序请求可完成，不只验证一个缓冲区能入队。
7. 测试后 gadget 已删除，再做一次模块卸载/重新加载通过。内核 tainted=0，
   本次 dmesg 未见 BUG、Oops、WARNING 或 panic；这不是长期稳定性证明。

Mac 原始 HID 报告监听未通过：设备已存在时 IOHIDManagerOpen 返回
`0xe00002e2`（kIOReturnNotPermitted）；没有将读取到零个报告当作成功。
因此本次证据为设备枚举、HID 描述符匹配和板端连续传输完成，不包含主机原始报告内容校验。

## 复测与剩余工作

上板独占、实验内核已启动、libcomposite/configfs 已准备且无其他 gadget 时运行：

```sh
sudo python3 crg-udc-check.py --exclusive --cycles 20 --keep-fd
```

入口在 [tools/crg-udc-check.py](../../tools/crg-udc-check.py)，只创建和删除自己的最小 gadget。
下一阶段需要实际键盘/鼠标输入、多功能端点组合、UAC2/存储、主机复位与休眠恢复验证。
当前驱动仍固定 peripheral、只支持单个实例，并拒绝板子系统休眠。
