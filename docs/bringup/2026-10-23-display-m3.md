## 本批实现

### OSD1 atomic 属性

原生 ENC2 路径提供标准 `alpha`、`rotation`、`pixel blend mode`、`zpos` 属性。
厂商 `drivers/drm/vpu-hw/meson_vpu_osd_mif.c` 的 global alpha 是
`VIU_OSD1_CTRL_STAT[20:12]`，DRM 16bit alpha 先右移 8bit，`0xff` 改为硬件单位值
`0x100`；X/Y reverse 为 `BLK0_CFG_W0[28]/[29]`。
控制字与地址、格式、stride 在同一 RDMA 描述符表提交，等待原有 RDMA 完成与 vsync
双条件后退休旧缓冲，沿用超时 pinning 和 error fence，未增加 IRQ 中的裸地址切换。

仅公开 `ROTATE_0 | REFLECT_X | REFLECT_Y`，不公开 90°/270°；双镜像可实现 180°效果。
当前 framebuffer 仍是 RGB888/XRGB8888/XBGR8888，因此 blend 只有 `None`，
不宣称 ARGB 像素 alpha、premultiplied 或 coverage。zpos 固定 0，没有假设存在第二层。
M1 固定 handoff 不添加这些属性，也不改它的寄存器写入范围。

`test_t7_osd.py` 编译执行实际驱动函数、厂商 alpha 转换与三个 MIF 函数，比较全部
65,536 个 alpha 值和 1,024 个初始寄存器/镜像组合。`test_t7_handoff.py` 实际执行
RDMA 锁存属性、RMFB、IRQ 先后顺序、60 次翻页/60 次 vsync、故障 pinning 和 error fence。
这些是离线寄存器和生命周期证据，不代表已验证半透明或镜像的物理输出。

### CEC

厂商 `common_drivers@4cfb128d36f8` 的 `cec_t7_data` 同时有 CECA v1、CECB v3，
使用 `cec_reg_group_a1`；板级 dtsi 明确只有 CEC_A pad。厂商默认选择 CECB 并通过
共享路由驱动 CEC_A，本批选择 CECA 直接驱动 GPIOW12，复用主线 `ao-cec.c` 的标准
adapter/TX/RX/逻辑地址接口，不引入厂商字符设备或私有消息 ABI。

继续核对时确认 T7 CECA 的逻辑地址寄存器不同于 GX：`CEC_LOGICAL_ADDR0/1`
是两个 8bit bitmap，不能写旧 `valid bit | address` slot。新分支对地址 0–15
写对应 bitmap，注销清空两半，保留旧 GX 编码；实际执行厂商 `ceca_addr_add()`
逐地址比较，并覆盖替换、无效地址、总线写失败。adapter 注销时先解除 notifier、
结束 threaded IRQ，再停 adapter，最后关闭时钟；顺序测试确认 IRQ 不会引用已释放的
adapter，停 adapter 的 MMIO 始终在时钟有效时进行。

同时修复原 AO 驱动的发布时序：先在时钟有效时屏蔽中断、初始化 reset 状态、注册 IRQ，
再连接 notifier 和发布 adapter。原先在发布后写 reset，用户态立即打开并配置设备时可能
被 probe 最后一次 reset 撤销。离线测试执行真实注册尾部，在发布回调内确定性模拟
首次打开，并覆盖 IRQ/notifier/adapter 三处注册失败的退出顺序和硬件屏蔽状态。

M3 DT 单独 claim `fe044000/14`（CECA）和 `fe044040/4`（CECB general/routing）。
第二项阻止另一 CECB 驱动并发注册并抢同一根线；只 masked update CECB bit4，
卸载/失败恢复该 bit 的原值，不整字覆盖其他字段。CECA 采用厂商 system clock/filter
设置，双方 share bit 均清零，走 CECA 原生 pad；不动 HDMI-IN 的 RX 控制寄存器。
时钟用已有 CCF `CLKID_CECA`（32768Hz）和 `CLKID_SYS_CEC`；IRQ 为 SPI179，
不复用 CECB SPI180、VIU1 vsync 或 RDMA IRQ。

`amlogic-t7-a311d2-khadas-vim4-display-m3.dtb` 继承 M2 显示/音频路径，仅增加 CECA；
默认 DTB、M1/M2 DTB 不启用该设备。现有配置 `CONFIG_CEC_MESON_AO=m` 可按 DT alias
加载驱动。TX bridge 使用 `DRM_BRIDGE_OP_HDMI_CEC_NOTIFIER` 和 `hdmi_cec_dev`，
由标准 bridge connector 注册 notifier、按 EDID 更新物理地址；`hpd_notify` 断开时
调用 `drm_connector_cec_phys_addr_invalidate()`，不依赖用户态下一次读 EDID。

`test_ao_cec_t7.py` 从厂商源码读取 A1 register group，执行厂商 filter 初始化与
`cec_ip_share_io(false, CEC_A)`，对照实际新驱动的 256 组初始值，并验证恢复只改
路由 bit。编译 DT 检查 IRQ、资源、时钟、pad 和 TX phandle；HDMI HPD 测试执行
connected/unknown/disconnected 三种状态的物理地址失效回调。
尚无 CEC 物理收发、仲裁重试或用户显示器互操作证据。

## 其余 M3：仍需实现的硬件路径

当前只接受线性 RGB framebuffer；TX 固定 8bit YUV444 BT.709 limited。

| 用户项目 | 当前状态 | 厂商依据与下一实现边界 |
|---|---|---|
| a：overlay/video、cursor、多层混合与缩放 | **未实现**；仅本批 OSD1 属性完成 | OSD2 `0x1a30`、OSD3 `0x3d80`、`meson_vpu_osdblend.c` 的输入 mux/排序/scope，以及 T7 `0x5aXX` scaler。需独立 MMIO claim、裁剪/缩放限制和多层同次 RDMA，先扩展每层引用与 fault pinning，再注册真实 plane |
| b：NV12/P010 直出 | **未实现** | `meson_vpu_video_wrapper.c` 经私有 vframe/VFM 转给 video_sink，不能直接接入主线 DRM；T7 用 `video_reg.c:vd_mif_reg_t7_array` 的 SC2 VD MIF，不能直接使用旧主线 G12 VD 地址。先做 NV12 双平面 pitch/offset/边界、canvas 所有权或 linear MIF、CSC 和 vsync；单独证明 P010 的 16bit 高位样本布局 |
| c：ARM AFBC | **未实现** | `meson_osd_afbc.c:t7_osd_afbc_hw_init` 使用独立的 T7 surface/status 组。必须验证 header/body 边界、modifier 子集和错误 IRQ，并在 decoder 不再取数后退休，不能仅等待 RDMA IRQ。ARM AFBC 与 Amlogic 视频压缩不能混用 |
| d：HDR/10bit/YUV420 | **未实现** | HDR blob、BT.2020 矩阵、formatter、DRM/AVI packet、deep-color PLL/PHY/ACR 必须一起实现。M2 保留 BT.709 矩阵，不能只发 HDR 元数据；420 的 TMDS 率与 VENC pixel rate 不同，现有单一 pixel_khz 计算必须拆开 |
| e：CEC | **离线候选** | 本批 CECA、标准 notifier 和 M3 DT；仍须用户在场的 CEC 显示器物理验证 |

厂商 `video_supported_drm_formats[]` 未列标准 `DRM_FORMAT_P010`；其私有/压缩
10bit YUV 不能当作 P010 已有支持。需继续核对 VD MIF bit-depth/endian/unpack，
算不清的布局拒绝，不靠格式名猜寄存器。HDR10/HLG、10bit 和 420 亦不因 T7 TX
硬件有能力就自动成为当前驱动能力。

后续多层提交需要所有 framebuffer 的 producer fence 在取数前完成，RMFB/disable
退休所有旧层；任一 RDMA/AFBC/VIU IRQ 缺失时不得释放可能仍在扫描的 DMA-buf。
新增层还需移植 SRAM 电源所有权：厂商 `am_meson_vpu_power_config()` 单独开启 OSD2、
OSD3、scaler、blend34 和 Mali AFBCD；T7 的 `vpu_vmod_mem_pd_switch_new()` 经
`vpu_mempd_psci_smc(vmod, state)` 调用 `0x82000093`，ID 是厂商 domain 数量加 vmod。
不能把 SC2/T5 的寄存器表直接写进显示驱动；应先核对固件 ID 与主线 genpd 的引用及失败
恢复，再让新增 plane 取数。本批没有新增该调用，也没有假设 U-Boot 已开启这些 SRAM。
VDIN 与显示继续不得分别修改 `VPU_WRARB_MODE_L2C1/2` 共享仲裁字，不允许扩大到
整块 VCBUS claim 或全 VPU reset。AFBC 与 canvas 如需共同使用，先落实统一 allocator
或 regmap masked-update 所有权，再接通消费者。

## 用户在场时的 M2 收尾

1. 先在普通 Chrome 打开 localhost 抓帧页，确认**新**视频帧和 BUER 音频片段实际上传；
   不用 Playwright 开摄像头/麦克风。记录设备标签、时间戳与样本 SHA，避免旧图误判。
2. SMPTE 和已确认执行的 GPU GLES 色条，逐模式取内部 16×16 中位数：每 RGB 通道
   误差 ≤16/255、灰条通道差 ≤8、GPU 黑条 ≤8。该容差含 UVC/浏览器转换，不等价总线精度。
3. `VIM4HDMITX` 播放 48k/S16_LE/2ch、997Hz，采集卡录音解码后核对 FFT 的
   987–1007Hz 能量；HDMI-IN 同时输入 440Hz，分别保存 TX 物理录音与 RX 解码证据。
4. HDMI-OUT 拔插后核对 HPD、EDID/mode 列表、音频恢复、RMFB 与 GPU 重开；
   1080p60 除约 60 flip event/s，还需物理相邻帧交替证明。
5. 当前采集卡 EDID 只有本轮目标的 720p50、1080p50/60、4K30；720p60/1440p60/4K60
   需要另接明确支持这些模式的显示器。4K60 另核对 SCDC、scrambling 和 1:40 回切。
6. 候选先 rebase 当时最新正式内核、重建、离线回归；持双锁一次性启动，核对已实测的
   硬件看门狗。最后回当时正式基线，五分钟编码/音频/HID/UDC/服务/taint 冒烟并清理。

M3 上板排在 M2 物理颜色通过之后。先测 primary alpha/镜像及不断 RX 的 RMFB/flip，
再用支持 CEC 的显示器运行 `cec-ctl` 物理地址、逻辑地址、TX/RX、拔插失效/重取；
USB 抓卡未必透传 CEC，不能将 adapter 注册当作物理收发通过。不做系统挂起/休眠。
以后每增加一项 plane/格式/HDR 能力，都追加对应布局、故障退休、共存与恢复用例，
不在一次窗口同时验收未分层验证的整条链路。
