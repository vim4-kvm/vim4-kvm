# 2026-10-20：7.x BCM43752 SDIO Wi-Fi

板上 SDIO BCM43752/2 原先缺少主线 brcmfmac 期望的文件名，未创建无线网口。
已将现有 Khadas 固件映射到主线名称，驱动成功加载，`wlan0` 可用，扫描得到
27 个网络，覆盖 2.4GHz 和 5GHz。用户要求自行验证客户端联网，未声称 DHCP、
路由器通信、互联网、吞吐或断线重连已经通过。

## 实现与验证

固件原文件由 `linux-board-package-noble-vim4` 安装，不在本仓库重新分发。
[准备工具](../../packaging/kernel-edge/prepare-wifi-firmware.py) 校验三个原文件摘要，
先检查所有目标冲突再创建相对符号链接；重复运行保持现有正确文件，创建失败回收
本次新链接，不覆盖用户文件。离线覆盖冲突、输入损坏、悬空链接和部分失败回滚。

| 原文件（/lib/firmware/brcm） | brcmfmac 使用的名称 |
|---|---|
| fw_bcm43752a2_ag.bin | brcmfmac43752-sdio.bin |
| clm_bcm43752a2_ag.blob | brcmfmac43752-sdio.clm_blob |
| nvram_ap6275s.txt | brcmfmac43752-sdio.khadas,vim4.txt |

保留 PCIe 固件和所有原始校准数据，不把 PCIe 文件冒充 SDIO 固件，不修改区域或功率。
安装入口只准备文件，不加载驱动、不更改网络连接：

```sh
sudo python3 packaging/kernel-edge/prepare-wifi-firmware.py
```

首次失败后 SDIO function 1、2 均未绑定；仅绑定 function 1 不会启动固件加载。
两者重新绑定后，日志确认 `BCM43752/2 ... version 18.35.387.23.88 ... FWID 01-16e134aa`。
此前的 missing firmware / HT timeout 日志是启动时失败，不能当作本轮重试后状态。
缺少可选 txcap_blob 有日志，固件和扫描仍成功，未伪造该文件消除日志。

NetworkManager 的无线电原本关闭，现已开启。首次立即 rescan 因 supplicant 尚未就绪
返回 unavailable，待接口 disconnected 后重扫成功。扫描只保留网络数量和频点，
没有在公共记录中列出 SSID、凭据或接入点标识。

板上唯一保存的无线配置是 AP/shared 热点；一次激活得到 10.42.0.1，不是客户端联网。
识别后已停止本次热点。测试临时设置 never-default 并恢复配置原值，有线 eth0 始终
保留默认路由。未新建客户端连接、未填密码；后续由用户自己选择网络验证。
蓝牙 hci0、SSH、有线连接和 KVM 保持运行。

## 复现与剩余边界

固件链接已持久化；仍需在后续新内核整包重启时检查自动 probe，不以运行中绑定
代替冷启动验收。当前 5.15 原固件文件未改，新增链接不会替换厂商驱动使用的名字。
AP 的客户端接入、Wi-Fi 省电／恢复、吞吐和管理页面完整流程尚未验收。

日志在 `logs/kernel-edge/edge-wifi-*`。其中 connection 记录的 connected 表示
NetworkManager 配置激活，实际为热点；router_ping_passed=false 不作为联网通过证明。
