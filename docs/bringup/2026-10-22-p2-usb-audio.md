## 端点与 Windows 离线结论

CRG 只有 5 个可分配 IN 端点。现有三个 HID、UAC2、盘各需 1 个，NCM/RNDIS
需要 bulk IN 加 notification IN 共 2 个。因此完整键盘＋绝对鼠标＋相对鼠标＋盘＋
UAC2＋网卡需要 7 个，不能同时暴露。只保留一个 HID 时理论预算为 5，但会损失
现有鼠标接口，本轮没有采用或验收这一组合。UAC2 已关闭反向流及音量/静音中断端点。

核对部署对应的 One-KVM helper 和 Linux `drivers/usb/gadget/function/f_rndis.c`：

- RNDIS control 为 class/subclass/protocol `02/02/ff`，data 为 `0a/00/00`；
  IAD 默认 `02/06/00`，含两个接口。bind 时动态分配 interface ID，并更新 IAD 和 union，
  不是直接使用定义处的初始 `bFirstInterface=0`。有 interrupt IN、bulk IN/OUT。
- configfs 实读 `os_desc/use=0`、`b_vendor_code=0x00`、`qw_sign` 为空；没有配置链接。
  helper 仅创建网卡实例并复制 MAC，不设置 OS 描述符；内核 RNDIS compatible ID
  缓冲由零初始化分配，未自动填入 `RNDIS`/`5162001`。
- 若后续要支持 Windows 自动绑定，需要独立实现并测试 OS 1.0 签名 `MSFT100`、
  非零且不冲突的 vendor request、目标 configuration 链接、接口 compatible ID，
  以及 Windows 实际驱动选择；这些不能由 Mac 枚举推断。本轮没有改描述符。

OS 描述符语义对照 [Microsoft OS 1.0 规范](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/microsoft-os-1-0-descriptors-specification)，
这属于离线文档核对，不是 Windows 上的实际请求抓包。

NCM/ECM 数据通信只有[此前记录](2026-10-21-edge-usb-functions.md)的历史证明；
本轮没有重测其 DHCP/数据传输，更没有 Windows RNDIS 数据证据。
