# 2026-10-15：One-KVM 正式启用低延迟播放

按用户要求将视频 playout-delay 0/0 策略提交至 One-KVM `e9de9eeb`，保留原编码设置，
构建并安装 `2.5.1+vim4.20261016.90`。610 项 Rust、15 项部署和 49 项工作区测试通过；
正式包的校验、动态库、sudoers、配置保留、真实升级和认证更新 API 验证通过。

正式二进制在独立临时账户下测试 H.264/H.265，各 100 秒含 60 秒真实 HDMI 全屏运动，
4K60/60Mbps、Chrome 155、有线 IPv4；两种编码包头均确认每秒约 60 个 0/0 扩展。
运动时实际缓冲分别为 4.55/3.55ms，结束运动后为 0.78/0.82ms。
同二进制 H.264 禁用扩展对照为 28.58/26.29ms；帧回调 P99 默认/低延迟为
50.0/50.1ms、最大 83.3/83.4ms，本轮未见前次 P99 差异持续出现。
H.265 P99 33.4ms、最大 50.0ms。三组均零统计丢包、丢帧、freeze，音频峰值约 0.10。
不把实际缓冲当成端到端延迟；长期、弱网和其他浏览器仍未覆盖。

测试结束恢复正常 One-KVM 与管理器，清除临时账户目录、测试服务、恢复定时器。
dpkg 文件校验、包审计与 board check 通过；HDMI InvocationID 和 EDID SHA256 均不变。
配置、指标和限制见 [延迟差异调查](../kvm-delay-causes.md)，证据在 `logs/onekvm-playout-release/`。
