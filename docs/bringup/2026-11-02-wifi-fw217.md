7.3 正式驱动、旧版固件扫描出错的位置见[厂商对照](2026-11-02-wifi-vendor-scan.md)。

两版构建标签均含 he_sralp，新版还含 btcdyn；标签不能证明本板吞吐或
蓝牙共存性能改善，本次没有测量这两项。

## 加密连接与主机驱动

第一次激活时 NetworkManager 的 wlan0 尚未 ready，未进入 escan；这次不能计入
扫描验证。等待设备 ready 后，正式驱动配 .217 固件能扫描并提交 join，但多次
在 wsec_key 返回 -52 后立即断开。5.15 的 wl_cfg80211.c 将 AES-CMAC
管理密钥映射到 CRYPTO_ALGO_BIP (13)，7.3 原来的 AES-CMAC 分支使用 AES-CCM (4)。
同时发现 5.15 dhd_sdio.c 接受最大 0x70 的发送窗口，7.3 的 0x40 限制导致
该固件持续产生 max tx seq number error。实验驱动针对 BCM43752 对齐这两处。
探针仅记录密钥编号、长度、算法和返回值，不记录密钥内容。

WCC 的 discovery BSS 适配原本只匹配 .88 的 FWID。当 .217 未进入该分支，
wpa_supplicant 每次创建 P2P 设备时都等不到 IF_ADD。STA 连接成功不能替代
discovery 验证，启用 .217 的 WCC 适配后另行计数。

修正密钥和窗口、仍使用旧 WCC 模块时，新固件连续 48/48 次连接成功。
48 次均记录到 key index 5、长度 16、算法 13；普通数据密钥仍为算法 4。
同一主驱动换回 .88，连续 24/24 成功。该对照表明单凭几十次成功不能将
差异归因于固件升级。新版完整候选的 SDPCM 接收头另取样 16 秒，390 帧
报告的可用窗口全部为 72 或 73，超过 7.3 原来的 64，处于 5.15 接受的范围内。

启用新版 FWID 对应的 WCC discovery/流控路径后，52 次完整激活均成功，
35558/35558 条探针事件保留。独立的 P2P 冒烟检查确认 STA 使用 SAE、PMF=2，
在 5200 和 2412 MHz 各完成一次 GO 创建、STA 网关通信和组删除。未测试真实
第二设备的协商及组内数据。对应内核分支 `wifi-43752-fw217`，依次为
管理密钥 7bfda5c015eaa、发送窗口 492cc81f84ce5、discovery 923aa01fdd7d4。

## 重现构建输入

从 0d0bdced8193 的干净源码可重放[三个内核提交](../../packaging/kernel/bcm43752-fw217.patch)。
本轮在独立 checkout 用 git am --committer-date-is-author-date 重放，得到的
源码树为 06adc9a93d927c29dda50428bf1692e357932813。固件程序来自上方固定
CoreELEC 提交的 firmware/brcm/fw_bcm43752a2_ag.bin；主仓不重新分发其字节。
在准备匹配的 uhd6 模块及镜像时，先运行原有的
[VIM4 固件准备工具](../../packaging/kernel/prepare-wifi-firmware.py)
生成校准和 CLM 别名，然后校验并安装单独取得的程序：

```sh
echo '3ff292ab216c13ce3019f6b4cc4234a15a81c8b553014b122f748efd9465676d  fw_bcm43752a2_ag.bin' | sha256sum -c - &&
sudo install -D -m 0644 fw_bcm43752a2_ag.bin \
  '/lib/firmware/updates/7.3.0-vim4kvm-uhd6+/brcm/brcmfmac43752-sdio.khadas,vim4.bin'
```

该路径限定内核 release 和板型。5.15 仍通过原厂文件名加载 .88。

## 安装验收与回退

在默认 FullKvm 安装 brcmfmac、brcmfmac-wcc 和限本 release 的板型固件。
正常重启三次，逐次核对两个已加载模块的 build ID、固件 FWID、原厂固件/
校准/CLM 哈希及 boot ID。安装前后按以下口径统计完整候选：

| 条件 | 保存网络连接 | 新增固件转储 |
|---|---:|---:|
| 临时装载完整候选，连续激活 | 52/52 | 0 |
| 12 对交替顺序、每次从独立启动与固件加载开始，取候选组 | 12/12 | 0 |
| 持久安装后，三次整板启动各测 1、1、48 次 | 50/50 | 0 |

共 114 次成功、114 次 join，所有归档仅含入场时已有的两份转储。旧固件配
密钥/窗口修正也通过配对的 12/12 次冷启动。原封不动的旧版正式组合另用历史
激活流程复测 42/42 成功。本轮未在原组合上重新触发已归档的故障，因而不能
仅凭本轮 A/B 确认某个固件内部修改消除了 PHY 异常。

已核对启动登记文件哈希、四项服务 active、UDC configured、Wi-Fi disabled、
默认路由 eth0，/boot 剩余 19 MiB。回退备份在根分区
`/var/backups/vim4-wifi-fw217`。需要恢复到本次安装前的模块和固件时，在板上运行
`sudo python3 /var/backups/vim4-wifi-fw217/rollback.py`，校验通过后正常重启。
备份校验包括升级前原件和升级后文件摘要，后续部署若已改变文件会拒绝覆盖。
