# 2026-10-15：UU 与网页滚轮对照及采样干扰

同一鼠标的用户对照确认官方 UU 直连 Mac 使用精确像素滚动，而 KVM 网页和
UU 经 KVM 都产生普通鼠标事件。用户强调网页没有 UU 那种突然加速，不能仅凭
两者都经过系统加速就判断手感相同。UU 转换层会把大增量拆成多份单格 HID 报告，
离线候选改为一份报告承载总刻度，保留余数及限幅；尚未部署或完成手感验收。

为观察鼠标写入而附加 strace 干扰了视频进程，用户报告明显卡顿后立即解除，
确认 TracerPid=0，发送帧率由约 23–34fps 恢复 60fps，用户确认恢复。
没有为恢复卡顿重启服务。测试期间另有 .14→.43 更新重启，USB 抓取未覆盖有效的
UU 滚动窗口，不能拿它证明拆包是本轮加速的直接原因。
原始日志、限制和下一步见 [UU 滚轮调查](../uu-scroll.md)。

用户随后授权部署：One-KVM `dac8693c` 打包为 `2.5.1+vim4.20261015.44`，
经 board.py 从 .43 升级，其他组件版本保持不变。校验和、安装、服务检查通过，
启动窗口后的网页复查 HTTP 200，板端二进制与本地 release SHA256 一致。
HDMI 服务未重启，新进程识别 4K60 输入；UU 重连后的实际视频与滚轮手感待验收。
