# 2026-10-16：PiKVM HDMI 音频周期性爆音

- 现象：PiKVM 网页声音约每秒一次“啪”，其他 KVM 应用无此问题。Mac 经 HDMI 输出
  440Hz 测试音，Chrome 解码后 PCM 的不连续点间隔为 1365ms 的整数倍，位置对 65536
  采样取模相同；同一时段 WebRTC 稳态零丢包、零补偿，排除网络。
- 根因：Janus 插件 acap.c 未设置 ALSA 周期与缓冲，TDM 驱动默认协商出 241 帧周期、
  65536 帧缓冲。板上以相同参数直接读 PCM 复现：每次环形缓冲回绕（帧 65536、196608、
  327680）的前 16 帧（64 字节）与上一圈同位置逐字节相同。`arecord` 默认 6000/24000
  不出现，所以单独录音测不出。

  | 周期 / 缓冲（帧） | 板上原始 PCM |
  |---|---|
  | 241 / 65536（原默认） | 每次回绕出错 |
  | 240 / 65536 | 每次回绕出错 |
  | 256 / 65536、960 / 65536 | 干净（6 s、15 s） |
  | 960 / 3840、240 / 3840 | 干净（15 s） |

  触发是小周期配最大缓冲；驱动为何在回绕处漏写 64 字节未查明，241/9600 另有一次
  非回绕点的不连续，原因未明。
- 修复：acap.c 设置周期为一个 Opus 帧（960）、缓冲 4 个周期，日志打印实际协商值。
  部署 vim4-pikvm `2.5.1+vim4.20261016.113`（开发构建），日志确认 960/3840。浏览器
  两轮 16 秒、一轮 60 秒录音，除启动 0.22 s 外零不连续（修复前 12 秒 5 次）。60 秒
  轮零丢包，仍有 5 次不规则的接收端补偿，对应偶发收包空档，非周期爆音，未继续处理。
- 部署检查因板上遗留的 `capture444-*` 临时失败单元返回非零，与本次无关，未清理。
  证据 `logs/pikvm-audio-wrap/`。
