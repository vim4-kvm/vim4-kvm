# GPU 候选维护与判读

本页管 Panfrost/Mesa 候选的维护约束；产品 kbase 合同见[kbase](gpu-kbase-7x.md)。
编译器和 GPU tone-map 工作暂停；保留实验，不据历史分数变更默认。
导航：[构建隔离](#构建隔离)、[正确性](#正确性先于性能)、[测量](#测量边界)。

## 构建隔离

来源和运行时锁见[GPU 构建器](../packaging/gpu/build.sh)及其锁文件，补丁选择以构建器为准。
使用私有前缀与逐进程 ICD，不覆盖系统 Mesa；loader 声明的最高版本不等于设备 API 能力。
内核候选必须核对完整匹配模块，单换 Image 可能仍运行旧 GPU 模块。
上游补丁只是[本地整理](../packaging/gpu/upstream/README.md)，未对外发送。

## 正确性先于性能

完整控制流系列曾出现错像素及 timeout，不能引用它的 FPS。
后续布局修复通过过全帧对照，但仍未追平厂商，见[修复窗口](bringup/2026-10-30-gpu-repair-window.md)。
最终 ISA 分支目标与 CFG 指针都要检查；同块回跳不能扣入前置块。
布局回归应经过真实编码器，静态统计一致不证明正确。
循环展开是绕过，不能当成循环编译器修复；语料膨胀和寄存器退化不能靠单探针高分抵消。

新候选先短执行并逐字节比较完整输出，确认无 timeout、MMU fault 或故障恢复增量，再测性能。
中心像素非零、noop 编译或离线模型都不能替代硬件正确性。
原算术依赖、分支和 clause 切换未由独立硬件计数分解，
不能把静态 tuple、NOP 或寄存器数直接换算成运行周期，更不能反推厂商 ISA。

## 测量边界

使用[比较器](../tools/gpu-compare.py)与[诊断器](../tools/gpu-diagnose.py)的实际参数。
冷提交主机等待、暖提交、GPU timer 和稳态吞吐分别报告；timer 失效样本不可用。
GPU 恢复发生在 boost 前的时间不能归为调频，低频采样也不能解析短突发。
诊断 trace 与普通性能轮分开；温度和驻留不是瓦数，不写猜测 PWM 或电压。
快轮询实测无明确收益，已不推广，不继续延长忙等，见[修复窗口](bringup/2026-10-30-gpu-repair-window.md)。

GPU 数据布局转换不等于 HDR tone mapping；HDR 主路径和颜色合同见[HDR](hdr.md)。
新增转换须保持输入退休后归还、stride 和容量一致；端到端管线吞吐、像素和队列增长分别验收。
未验完整 CTS、跨设备同步和功耗的项目不能从 API 查询或短测外推。
