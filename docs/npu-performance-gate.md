# NPU性能：历史波动分析与多启动门禁

离线分析后已完成[四启动对实测](bringup/2026-10-30-npu-boot-pairs.md)：
VGG16/DenseNet/YOLO均值配对差为+4.050%/+2.346%/−0.352%，总体仍不确定，不pin。
DDR与背景计数观测有缺口，VGG16和DenseNet联合上界超过5%。没有证据闭合的可修开销，
因此不改内核、不构建uhd3。未动GPU文件、未push/pin。保页例外仍为**用户已于 2026-10-30 接受**。
历史单组超过5%的事实保留；它不足以独立证明跨启动存在稳定退化，也不能据此宣称差距不存在。

## 数据与统计单位

[汇总CSV](data/npu-timing-20261030.csv)含22组原始result.json的路径及SHA、样本数、均值、
中位数/MAD、CV、P99/max、前/后20%中位数、四分段中位数、lag-1及上须计数。
数据为本机build/npu-board-20261030的旧5.15参考，r6/r8/r10的npu2/3/4，
r11/evidence的uhd2及其前后5.15。原始samples已经去首轮，不能再去一次。
中位数用statistics.median；P99为排序后ceil(.99*n)；CV用样本标准差/均值；
上须为Q3+1.5*IQR，仅描述尾部，不删样本；首尾差为末20%/前20%中位数-1。
lag-1以全组均值中心化的相邻协方差/全组平方和计算，未去趋势，不能直接当独立样本数。
分析脚本及输出在build/npu-variance，CSV不含模型二进制，不改写任何原始记录。

**一次启动内的100轮不是100次启动。** npu2/3修改过驱动及候选配置，不能把它们全部
当成同一系统的独立重复；npu2/3的YOLO第三输出错误，其耗时不参与等量工作性能资格。
npu3故障后的104ms路径属于错误恢复异常，不能混入健康启动方差估计。
真正相同源码/有效配置的npu4与uhd2也只有各一次启动，且release/构建产物不同。
现有数据支持原判定方法不够稳健，但不足以估计“总体启动波动就是±5%”。

## CPU侧和平台路径：按当前可能性排序

7.3行号相对VM ~/src/linux-7.3-npu-integration@f71b5c6289cb3；厂商路径在主仓
common_drivers/drivers/adla/kmd；这里只读源码，配置默认值不是板上实际governor证明。

1. **CPU放置/唤醒、上下文热身与外部负载：最优先排查，尚未定因。**
   两簇不等价：7.3 amlogic-t7.dtsi:85–100为A73，:163起为A53。
   两版adlak_os.c:400–405都走>=5.9的sched_set_fifo，内核5.15 kernel/sched/core.c:7819、
   7.3 kernel/sched/syscalls.c:812均设FIFO/50；RR/99分支不生效，注释“最高优先级”不准确。
   kthread_cpuid默认-1（7.3 :425–455；厂商:422–450），没有固定CPU；
   r10/phases-khadas/initial.json实际worker允许0–7，trace曾在CPU1运行，IRQ计数在CPU0。
   两版adlak_interrupt.c:70都request_irq，没有显式affinity；不能假定两次启动放置相同。
   7.3 uhd2.config:649编译默认performance，5.15 packaging/kernel/vim4.config:591为schedutil；
   用户态/热控可覆盖。uhd2唯一后采快照policy0/4为2208000/2016000kHz、温度49.9–54.1°C，
   没有完整时序或5.15配对频率。DTS:240–248虽声明深idle退出5000µs，:243却明确disabled，
   因而不能把7.3的差距归于该深睡状态；浅idle/调度唤醒仍缺实际计数，不按标称延迟推算。
2. **计时外工作改变下一轮状态：有明确路径，影响量未知。**
   tools/npu-probe.c:68–75只计SDK input_set/output_get，:79–106打印、写全部输出并扫描float。
   它们不在elapsed内，但会影响CPU、页缓存、DDR和下一轮唤醒，YOLO每轮约4.8MB尤甚。
   各组新建context（:49–51），没有CPU/DDR/温度稳定条件，也没有逐轮CPU号/间隔时间戳。
   SDK的float32输出获取还可能含CPU处理；闭源内部未分段，elapsed不能等同NPU纯执行时间，
   也不能跨启动相减trace时间推算CPU开销百分比。
3. **DDR/DMC状态：影响机制合理，证据最缺。**
   现存日志没有配对DDR频率。7.3 T7 DTS未找到DMC devfreq节点，启用governor配置不代表
   DDR设备存在。厂商drivers/memory_debug/ddr_tool/ddr_bandwidth.c:898–919为只读freq；
   PXP_DEBUG下:859–868的写口只改pxp_debug_freq，是测量覆盖值，绝不能当锁DDR频率。
   不扫寄存器、不写该口；缺失读回时不能宣称DDR已经对齐。
4. **NPU时钟/PM：热循环逐次挂起的可能性低，尚非完全排除。**
   7.3 platform_config.c:63的DPM周期300ms，inference.c:120–139统计闲周期，:333–344
   达10个才请求停钟，约3秒量级；platform_config.c:473–498才put_autosuspend，延迟另300ms。
   不是每个INVOKE后就put。r10正常/恢复trace均799999987Hz、IRQ等待约1.53ms；
   uhd2并行也读回800MHz，结束0Hz/suspended。缺uhd2独立组PM迁移时序，不能假定完全相同。
   尤其debugfs.c:347–353的clk_core_show只是打印clk_core_freq_real缓存，
   platform_config.c:438才在设频路径更新；旧sysfs日志不是逐调用实时测频。
   phase trace取clk_get_rate是CCF提供者读回，也不等于独立物理测频。
   power/control=on只约束runtime PM，不能阻止厂商DPM直接CCF停钟，不能拿它冒充锁NPU时钟。
5. **缓存/IOVA/ioctl额外开销：值得量化，尚无可安全删减的证据。**
   两版port/os/linux/mm/adlak_mm_os_common.c:520–594逐行相同：全缓冲req.bytes或指定partial，
   flush为TO_DEVICE，invalidate为FROM_DEVICE，SG路径同样选择范围。不能说7.3新增全量同步，
   也不能凭模型输出长度缩减SDK请求范围；底层DMA实现/实际调用次数与字节量仍可能不同。
   两版fops.c:270附近均有描述复制、dev_mutex、提交和回拷；7.3 submit.c:994起多了边界检查，
   :1539–1540保留worker通知/yield，:1860等待。npu4与uhd2这些代码相同，
   检查成本可能真实存在，但不能只据该次6%删安全检查；现有trace不覆盖整个ioctl创建路径。

## 新门禁：预先登记、多启动、三态结论

目标≤30分钟，采用**ABABABABA**：A=5.15，B=同一uhd2载荷，4个不重叠AB对，
每边至少4次独立启动；末A只作漂移与恢复核对，不替换较慢的A参考。
启动/上下文/轮次分层保存，不能把不同启动全部轮次池化后bootstrap出虚假窄CI。

- 每启动固定10秒稳定期，每模型3个独立context。DenseNet/VGG每context1000轮去前50；
  YOLO每context101轮去前10，保留冷样本另报；AB同对模型次序相同，各对轮换模型顺序。
  这是新协议，旧“只去首轮”结果另列，不拼接。输出始终全量校验，不按延迟删点或重跑挑组。
  按probe.log原始iteration索引去[0,49]或[0,9]；已有result.samples已去0，不能再错位去一次。
- 保持同SDK/probe/输入SHA、khadas、无视频/其他负载。输出暂存已存在tmpfs，YOLO一次仅约0.5GB，
  每context核验清单后回收自己目录，限定容量，不能挤压RAM/CMA；不在计时期间归档/下载/编译。
  改了输出存放策略，两内核都重新采，不能套用旧基线。样本内/块间P50/P99/max和均值都保留。
  停流后须确认无接收者且采集/编码计数静止；若仍推进，只能对齐固定背景并单列，不能假定无负载。
- 每boot先求3个context暖均值的平均与3个context中位数的中位数；每AB对分别求均值比与
  中位数比的百分比差d_j。报告4对原值、等权平均配对差及CI，不把B1/B2当成数千次独立启动。
- 主要门槛仍为**平均退化≤5%**。报告配对均值差的双侧95% Student-t CI，df=3；
  全三模型通过另要求每模型单侧上界 U=mean(d)+t_(1-.05/3,3)*sd(d)/sqrt(4)≤5%，
  以Bonferroni限制三模型整体错误通过风险。中位数效应用同一启动层配对方法报告95% CI，
  仅辅助解释，不替换均值门槛。下界>5判有退化证据，跨界或条件不齐判**不确定**，不直接判通过。
- t区间依赖启动对误差近似独立、无明显漂移及近似正态；4对不能验证这些假设，功效有限。
  不满足时保持不确定，另约反向顺序窗口增加启动对；不靠更多同boot轮次“补显著性”。
  4对也不能给无分布假设的有限95%总体中位效应区间，不用小样本百分位bootstrap伪装解决。

## 状态对齐、记录与恢复

在首A/B只盘点具名sysfs能力，备份原值，不依赖猜测路径：

- CPU：读取policy*/related_cpus、governor、available_frequencies、min/max、cur_freq和time_in_state。
  在两边已公开OPP交集中选共同频率，使用已有performance/min/max选项固定两簇；不写电压/PWM。
  cur_freq是框架读回代理，不冒充物理测量。若约束/热控不能满足，整窗保留数据并标条件不齐。
- 放置：先确认两边CPU拓扑，固定probe/SDK线程和worker到相同已在线A73 CPU集合；
  用taskset及既有/proc/irq/IRQ/smp_affinity_list控制自己的NPU路径，不改优先级。
  记录所有线程实际CPU/迁移、effective_affinity；不把写module kthread_cpuid当作已绑定现存线程。
- DDR：只有两边都有已审查过的真实devfreq/clock读回与合格控制时才固定共同频点；
  目前缺该能力证明，不现场编造节点/锁频。可报告端到端平台差，但“同DDR频点纯驱动差”资格
  保持不确定；缺口是后续只读观测前置项，不用debug freq覆盖值或盲读MMIO补齐。
- NPU：对齐已验证忙态800MHz，记录clk_core、runtime_status、活动/挂起时间、IRQ和PM迁移。
  标注clk_core为缓存值；短诊断补既有CCF设频/启停事件及7.3 phase取频，不把缓存采样当硬件恒频证明。
  不改变DPM策略来掩盖恢复开销；冷启动单列，热样本若观察到停钟/频点变化则标记条件异常。
- 以同一1Hz记录器采CPU/DDR/NPU可得频率、各thermal_zone类型/温度，记录缺失字段而非填0。
  预先规定AB热样本温度中位数差≤3°C、频点一致，超限整窗不确定，不选择性删除坏对。
  独立短诊断用tracefs过滤自己的NPU PID/worker/IRQ，量化ioctl、sched_wakeup/switch和缓存字节；
  不ptrace视频进程、不将诊断开启组混入性能CI。字段不可得就明确不可得。

每次切核前恢复本kernel原governor/min/max、进程亲和和IRQ亲和；最终A再核对原值。
若任一步失败，先回默认A并恢复文件/服务/锁；参数不持久化、不覆盖启动配置、不停其他服务。
频率对齐后的结果须标“受控工况”，不等于默认省电策略下产品性能已经通过。

## 下一窗口预算与结论

0–4分钟持锁核对、备份与能力盘点；若没有两kernel的能力清单，先只盘点A/B并回A，
新增两次重启也计入预算，不把预检启动充作受控样本。
4–24分钟执行四AB对及末A：每启动约30–60秒的稳定/采样/校验与最多60秒重启预算；
24–28分钟收尾、原值与哈希/服务/UDC核对，留2分钟余量。
Dense/VGG每boot2850暖样本，YOLO273，启动数优先于继续增加同boot轮数。
若启动/能力对齐超预算，缩减为明确的探索窗口，不能把少于4对的结果自动升级为确认性通过。
本窗不同时做六分钟视频并行、错误注入或真实复位失败；那些已测范围不混入独立性能门禁。
仍不发HID、不测声音、不写电压/PWM，不pin/push，板子失联无法恢复就停止报告。

当前结论是**真实、稳定的跨内核差距尚未确定；尚未获得可靠的≤5%资格证明**。
保留uhd2单组失败事实及npu4通过历史，先改测量设计，不凭假设改驱动或生成uhd3。
离线分析提交时主仓unittest为311项、7跳过，OK；其后上板与本轮验证见实测记录。
