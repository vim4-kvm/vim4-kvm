# 5.15 / 7.3 整夜性能基线执行计划

摘要：**仅计划，等待用户确认开跑时间，未排定或启动夜间任务。** 本次
[短窗口](bringup/2026-10-23-vendor-boot-gpu.md)已验证5.15一次性启动、SSH及默认7.3返回。
完整协议仍为 [性能基线](performance-baseline.md)，三组A/B/A不能压缩成一次短跑。
按细化后的串行矩阵预计连续占板22–24小时（跨整夜及次日）；若仅提供8小时，拆成
多个夜间窗口并保留“未完成”状态。原协议15–20小时是初步量级，不能覆盖全部扩展项。

## 开跑前完成的准备

- 重新pull、读sources.toml，固定当时已部署7.3的build ID、Image/DTB/完整模块及
  应用/插件/工具/浏览器哈希。分支上已合入但未部署的M1/Wave5改动不能算本轮运行基线。
- 先离线完成所有构建、素材准备和工具依赖；两端使用相同公共用户态，不能在轮次间升级。
  记录生产默认DVFS；固定频率诊断另列，不改电压、EDID、引导固件或持久服务配置。
- 申请连续双锁窗口，锁顺序统一为board→heavy；等待期间不改板子。源Mac与网络对端也
  不编译、不跑其他测试。取锁后先确认无已挂载虚拟盘、无额外观看者及USB输入任务。
- 对5.15与7.3的硬件编码/GStreamer元素做清单；固定素材与参考解码校验在采样前完成。
  每项新输出目录、原始stdout/stderr/退出码、1Hz传感器记录，失败样本保留。
- 本次5.15仅有Mesa软件渲染，缺匹配libMali用户态；不能把19分当厂商Mali基准。
  GPU硬件对照须先在独立授权窗口准备合法且匹配的用户态栈，再冻结两边EGL库与实际
  surface尺寸；本计划不在夜间临时安装/修复。未就绪则该项标测量缺失，整套不能宣称性能追平。
- 7.3未支持的vdec codec标能力缺失，禁止夜间加载未过安全门禁的解码候选。音频绝对
  延迟/纯USB报告/整板功率需要外部仪器；无设备时照实标测量缺失，不以AV偏移或温度代替。
- 目前只证明正常重启返回默认项。无人值守前仍需已验证的独立RESET执行器/看门狗；
  未具备时按有人可现场RESET的窗口执行。启动超时停止，不自动重复尝试或修驱动。

## 顺序与预算

A为5.15.137-vim4kvm，B为开跑时固定的正式7.3；所有A均由RAM sysboot一次性选择，
默认始终B。执行序列 **A0→B1→A1→B2→A2→B3→A3→B恢复**，中间A同时作为相邻
组的后/前对照，每个配置仍有三组独立B样本。每次启动均核对真实build ID和cmdline。
若中间升级、换配置/浏览器或受干扰，相关组作废并保留，不把不同配置拼成配对。

| 相对开跑时间 | 内容与退出条件 |
|---|---|
| T+00:00–00:45 | 双锁入场清单、健康快照、LUN/PD、源端稳定、温度起点；不符即停止 |
| T+00:45–18:15 | 七个采样块，每块约150分钟，按下表固定顺序；每块冷却至共同温区，原生和应用负载串行 |
| T+18:15–20:15 | 两内核各H.264/H.265同连接30分钟耐久；首尾120秒标记窗口，保留静止/运动段；如已包含在采样块，扣减对应时间 |
| T+20:15–21:00 | 补冷/热启动端点及外部音频/USB/功率仪器记录，设备未具备则明确缺失 |
| T+21:00–21:30 | 回正式B，五分钟画面/一路编码/HID、taint及新oops检查，核对受保护文件与设置，清理本轮临时文件并立即释放锁 |
| 另留0–2小时 | 失败诊断、冷却或安全返回余量；不把恢复时间挤掉。回退失败停止任务并报告现场状态 |

锁释放后才跑离线图像/码流分析、compare、全套仓库检查与fetch/rebase/提交推送。
不为整理报告或等待用户回复继续占板。

## 每块固定矩阵

| 顺序 | 同条件项目 | 预计时间 |
|---|---|---:|
| 1 | 1080p60/2160p60；纯采集、H.264/H.265各12/60Mbps、JPEG Q80；每项900帧预热+7200帧（≥120秒），原生应用暂停后恢复 | 30分钟 |
| 2 | 同分辨率/codec/码率的单观看者延迟及无像素回读呈现配对，15秒预热+120秒；音频开启，实际网络路径固定 | 40分钟 |
| 3 | AV同步180秒/编码；HID发送→原生事件20轮；CPU每簇单核/全核、内存单/多线程读写120秒/项 | 30分钟 |
| 4 | 固定eMMC scratch普通文件的顺序/4K随机读写、固定有线网络正反向，15秒预热+120秒/项；扩展SD/USB/Wi-Fi另预留窗口 | 20分钟 |
| 5 | 同场景GPU（具备匹配用户态且同surface时）、空闲300秒、CPU满载600秒与KVM负载温度/DVFS；同一1Hz传感器记录，冷却/启动开销 | 30分钟起 |

上述150分钟是排队量级，不能到时就截断样本；GPU完整场景、慢JPEG、热稳定或HID
样本不足会延长。扩展接口、逐codec解码、绝对音频P99（至少1000脉冲）另加4–8小时。
若仅8小时一晚，只安排初筛或缩减矩阵的一组完整A/B/A；完整矩阵一组含准备已需
约8–9小时，应另约足够长的窗口。跨晚重新入场核对，环境温度/配置不匹配的组需重测，
不能以一夜初筛冒充完整验收。

## 判定与交付

逐配置逐指标套用既定门槛：吞吐≥95%；P50/P95/P99延迟增加不超过max(5%,2ms)；
丢帧/丢包/冻结/内容错误为0；功率≤105%，同风扇环境温升增加≤2°C。先审查A两侧漂移、
源帧推进、实际分辨率/codec/码率、时钟校准与样本数，再生成单指标compare输入。
有限吞吐不能证明峰值能力，能力/测量缺失不得写0、不得计入“通过”。

最终交付原始证据索引、版本与配置清单、三组结果及失败轮次、性能表逐行状态、
安全返回及清理证明；有缺失项时明确未完成，不写“全部能力/性能已追平”。
